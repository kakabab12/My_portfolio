## 3. 실행 명령

### TurtleBot3 bringup

OpenCR 포트가 전원 재연결 후 `/dev/ttyACM0`에서 `/dev/ttyACM1`로 변경되었으므로 현재는 반드시 포트를 명시합니다.

```bash
source /opt/ros/humble/setup.bash
export TURTLEBOT3_MODEL=burger
export LDS_MODEL=LDS-02
ros2 launch turtlebot3_bringup robot.launch.py usb_port:=/dev/ttyACM1
```

포트는 부팅이나 USB 재연결 후 다시 바뀔 수 있으므로 실행 전에 확인합니다.

```bash
ls -l /dev/ttyACM* /dev/ttyUSB* /dev/video*
```

### 제스처 서버

기본 `python3`는 Miniconda Python 3.13을 가리켜 ROS/제스처 패키지와 호환되지 않습니다. 제스처 서버는 저장소의 Python 3.10 가상환경으로 실행합니다.

```bash
cd /home/user/sw/robot
.venv/bin/python -m src.server.app
```

제스처 의존성은 `.venv/lib/python3.10/site-packages`에 설치되어 있습니다.

### ROS 2 제스처 브리지

브리지는 ROS 2 Humble의 `rclpy`와 ABI가 맞는 시스템 Python 3.10을 사용해야 합니다.

```bash
cd /home/user/sw/robot
source /opt/ros/humble/setup.bash
/usr/bin/python3 ros2_bridge/cmd_vel_bridge.py --base-url http://127.0.0.1:5000
```

### 권장 실행 순서

1. SMPS/OpenCR 전원을 켭니다.
2. 장치 포트를 확인합니다.
3. TurtleBot3 bringup을 실행합니다.
4. 제스처 서버를 실행합니다.
5. `/health`와 `/cmd`를 확인합니다.
6. 마지막으로 ROS 2 제스처 브리지를 실행합니다.

```bash
curl http://127.0.0.1:5000/health
curl http://127.0.0.1:5000/cmd
ros2 topic info /cmd_vel -v
ros2 topic echo /sensor_state --once
```

## 4. 오늘 반영한 제스처 동작 사양

### 기본 주행

- 손바닥 모양(`open`)일 때만 방향 주행이 허용됩니다.
- 손이 없거나 주먹이거나 중앙 존이면 즉시 0 속도를 냅니다.
- 잠금 토글 모드는 제거했습니다. 서버 시작 직후 `armed=true`입니다.
- 손이 처음 검출된 위치를 중앙 원점으로 잡습니다.
- 현재 고정 속도:
  - 전진/후진: `0.12 m/s`
  - 좌/우 회전: `0.8 rad/s`

### 민감도와 커서 안정화

- `cursor_sensitivity`: `3.0`에서 `2.0`으로 낮춤.
- One Euro 필터 `beta`: `0.3`에서 `0.15`로 낮춰 순간적인 랜드마크 오차 반영을 완화함.
- 활성 카메라가 0과 2 사이에서 바뀌면 이전 카메라 픽셀 좌표를 이어 쓰지 않고 새 위치를 중앙으로 재보정함.
- 화면의 제스처 커서 점은 영상 밖으로 나가지 않습니다.
- 점 반지름 9px 전체가 보이도록 네 변에서 9px 여백으로 표시 좌표를 제한합니다.
- 화면 표시만 제한하며 실제 방향 판정용 오프셋은 제한하지 않습니다.

### 주먹 3회 중앙 재설정

- `주먹 -> 손바닥`을 3회 반복하면 세 번째로 펼친 순간의 검지 끝 위치를 새 중앙 원점으로 설정합니다.
- 첫 번째 횟수부터 5초 안에 세 번을 완료해야 합니다.
- 재설정 순간 출력은 중앙 존이므로 정지합니다.
- 손을 놓치거나 `fist/open` 이외 손모양이 끼면 횟수가 초기화됩니다.
- 주먹 상태에서는 기존 안전 규칙에 따라 항상 정지합니다.

## 6. 오늘 발견한 장애와 해결 내용

### OpenCR은 잡히지만 모터가 움직이지 않았던 문제

처음에는 `/battery_state`와 `/sensor_state`가 다음 상태였습니다.

```text
battery: 0.07V
present: false
torque: false
```

`/motor_power` 서비스도 다음 오류로 실패했습니다.

```text
Failed transmit instruction packet
```

원인은 OpenCR이 USB 전원으로 통신만 되고 모터용 12V 전원이 전달되지 않았기 때문입니다. 12V 5A SMPS를 정상 연결한 후 전압이 약 12.15V, torque=true가 되었습니다.

### 전원 재연결 후 OpenCR 포트 변경

OpenCR이 `/dev/ttyACM0`에서 `/dev/ttyACM1`로 바뀌었습니다. 기본 `robot.launch.py`는 `/dev/ttyACM0`을 사용하므로 다음처럼 명시해야 했습니다.

```bash
ros2 launch turtlebot3_bringup robot.launch.py usb_port:=/dev/ttyACM1
```

### Python 환경 충돌

- 셸의 `python3`: Miniconda Python 3.13
- ROS 2 Humble `rclpy`: 시스템 Python 3.10용
- 제스처 엔진: `.venv/bin/python` Python 3.10

따라서 실행기를 섞지 않습니다.

### ROS 2 그래프가 일시적으로 불완전하게 보이는 문제

`ros2 node list` 또는 `ros2 topic info`가 일시적으로 일부 노드/endpoint를 못 찾으면 daemon 캐시를 갱신합니다.

```bash
source /opt/ros/humble/setup.bash
ros2 daemon stop
ros2 daemon start
sleep 2
ros2 node list
ros2 topic info /cmd_vel
```

## 7. 알려진 기술 부채 및 주의점

### 브리지 Ctrl+C 종료 예외

`cmd_vel_bridge.py`를 Ctrl+C로 종료할 때 ROS context가 먼저 닫힌 뒤 `stop_robot()`이 publish를 시도해 다음 예외가 발생할 수 있습니다.

```text
RCLError: Failed to publish: publisher's context is invalid
```

실행 중 기능에는 문제가 없지만 종료 처리를 다음 작업에서 고치는 것이 좋습니다. shutdown 전에 0 Twist를 발행하거나 context 유효성을 확인해야 합니다.

### Flask 요청 로그 과다

브리지가 `/cmd`를 20Hz로 폴링하므로 Werkzeug access log가 매우 많이 쌓이고 터미널 출력도 커집니다. `/cmd` access log를 끄거나 rate-limit된 상태 로그로 교체하는 것이 좋습니다.

### 현재 제스처 브리지는 `/cmd_vel`에 직접 발행

현재는 제스처 단독 제어 단계라 괜찮지만 Nav2 자율주행과 통합할 때는 그대로 사용하면 안 됩니다. Nav2와 제스처가 `/cmd_vel`에서 경쟁하게 됩니다.

권장 통합 구조:

```text
Nav2        -> /cmd_vel_auto ----┐
                                 ├-> command mux/mode manager -> /cmd_vel
Gesture    -> /cmd_vel_gesture --┘
```

기본 모드는 AUTO, 협소구역에서 GESTURE로 전환하고, 전환 중간에는 STOP 상태를 두어 0 속도를 보장합니다. 수동 조작 중에도 SLAM/위치 추정은 계속 유지하고 Nav2 이동 명령만 차단하는 방향이 좋습니다.
