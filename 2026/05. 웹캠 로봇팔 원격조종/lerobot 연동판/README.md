# MediaPipe 팔 추적 -> SO-ARM-101 텔레오퍼레이션

웹캠으로 **왼팔**(어깨 → 팔꿈치 → 손목)과 손을 추적해서 SO-ARM-101 6축을 실시간으로 움직입니다.
랜드마크의 **x, y 좌표만** 씁니다 (z와 world landmark는 쓰지 않습니다).

## 파일

| 파일 | 역할 |
| --- | --- |
| `download_models.py` | MediaPipe Tasks 모델(.task) 다운로드 |
| `arm_tracker.py` | 랜드마크 → 6축 관절값 변환 (핵심 로직) |
| `teleop_so101.py` | 카메라 루프 + 로봇 전송 |

## 카메라 위치: 정면 vs 측면

`--view front` (기본) / `--view side` 로 고릅니다. 측면 촬영은 팔이 움직이는 시상면이
카메라와 나란해져서 **어깨·팔꿈치 각도가 정확해지는** 대신, **좌우 정보가 화면에
존재하지 않아 `shoulder_pan` 을 구할 수 없습니다.**

```
           [카메라]
               ▲
               │  --view side
   어깨 ── 팔꿈치 ── 손목
```

측면 모드에서 `shoulder_pan` 은 `--pan` 으로 준 값에 고정됩니다 (기본 0).
몸이 향한 방향(코 위치)으로 앞/뒤를 자동 판별하므로 카메라가 좌우 어느 쪽에 있어도 됩니다.
**카메라와 가까운 쪽 팔**을 써야 합니다. 반대쪽 팔은 몸에 가려서 추적이 튑니다.

| 관절 | `--view front` | `--view side` |
| --- | --- | --- |
| `shoulder_pan` | 손목 좌우 오프셋 | **관측 불가 → 고정** |
| `shoulder_lift` | 팔꿈치 높이 (y) | 위팔 굴곡각 (0°=차렷, 90°=앞으로 수평, 180°=만세) |
| `elbow_flex` | 사잇각 | 사잇각 (측면이 더 정확) |
| `wrist_flex` | 사잇각 | 사잇각 (측면이 더 정확) |
| `wrist_roll` | 손바닥 폭 근사 | 손을 옆에서 보므로 **더 부정확** |
| `gripper` | 손끝 거리 | 손끝 거리 |

## 관절 매핑 상세 (x, y 만)

| 관절 | 사람 동작 | 계산 |
| --- | --- | --- |
| `shoulder_pan` | 팔을 좌우로 | 손목의 어깨 대비 x 오프셋 / 위팔 길이 |
| `shoulder_lift` | 팔을 위아래로 | 팔꿈치의 어깨 대비 y 오프셋 / 위팔 길이 (=위팔 기울기의 sin값) |
| `elbow_flex` | 팔꿈치 접기/펴기 | 위팔–아래팔 사잇각 (180°=폄, 30°=접음) |
| `wrist_flex` | 손목 꺾기 | 아래팔 벡터 vs 손바닥 벡터 사잇각 |
| `wrist_roll` | 손 돌리기 | 손바닥 가로폭 비율 (xy만으론 롤을 직접 못 구해 근사) |
| `gripper` | 엄지 ↔ 나머지 4손가락 | 손끝 평균거리 / 손바닥 길이 |

몸통 길이(어깨–엉덩이)로 정규화하므로 카메라와의 거리가 변해도 값이 크게 흔들리지 않습니다.
좌우 바깥 방향은 반대쪽 어깨 위치로 자동 판별해서 미러 여부와 무관하게 동작합니다.

## 자연스러운 동작을 위한 2단계 필터링

랜드마크 좌표는 프레임마다 픽셀 단위로 떨리기 때문에, 그대로 관절값으로 쓰면 로봇이
미세하게 파르르 떱니다. 이를 두 단계로 해결합니다.

**1) 1€ Filter** (`arm_tracker.py` 의 `OneEuroFilter`, Casiez, Roussel & Vogel — CHI 2012)
랜드마크 → 관절값 변환 직후에 겁니다. 손이 멈춰 있을 때는 강하게 눌러 떨림을 없애고,
빠르게 움직일 때는 컷오프를 올려 지연을 줄이는 **속도 적응형** 저역통과 필터입니다.
고정 알파의 지수이동평균(EMA)과 달리 "부드러움 vs 반응성"을 자동으로 절충해줍니다.

**2) Critically-damped SmoothDamp** (`teleop_so101.py` 의 `smooth_damp`,
Game Programming Gems 4 / Unity `Mathf.SmoothDamp` 와 동일한 공식)
필터링된 목표값을 로봇에 그대로 튈 각도씩 전송하지 않고, 실제 경과시간(dt) 기준으로
가속·감속이 이어지는 곡선을 그리며 따라갑니다. 목표를 지나쳐 진동하지 않도록
오버슈트 방지 로직이 들어 있습니다. 이전의 "프레임당 고정 각도" 방식은 프레임레이트가
흔들리면 실제 속도도 같이 흔들렸는데, 이제는 `--max-speed` (도/초) 로 물리적으로
의미 있는 속도 상한을 겁니다.

## 실행

**Python 3.11 로 실행해야 한다** (`lerobot` + `scservo_sdk` 가 여기 설치돼 있음).
아래 명령의 `python` 은 `%LOCALAPPDATA%\Programs\Python\Python311\python.exe` 를 가리킵니다.

모델은 이미 `models/` 에 받아뒀습니다. 다시 받으려면:

```bash
python download_models.py
```

### 1) 로봇 없이 매핑 확인

```bash
python teleop_so101.py --dry-run
```

화면에 관절값만 띄워서 매핑을 먼저 확인합니다.

### 2) 로봇 캘리브레이션 (최초 1회)

`~/.cache/huggingface/lerobot/calibration/robots/so_follower/so101.json` 이 아직 없습니다.
처음 `--port` 로 실행하면 터미널에서 각 관절을 끝까지 움직이라는 안내가 나옵니다.
로봇이 실제로 움직이므로 주변을 치우고 직접 진행해야 합니다.

### 3) 실제 구동

```bash
python teleop_so101.py --port COM3
```

ESC 또는 `q` 로 종료. 종료 시 로봇은 안전하게 disconnect 됩니다.

## 안전 / 튜닝 옵션

| 옵션 | 기본값 | 의미 |
| --- | --- | --- |
| `--beta` | 0.4 | 1€ 필터 속도 계수. 클수록 빠른 동작의 지연이 줄지만 떨림도 늘어남 |
| `--min-cutoff` | 1.0 | 1€ 필터 최소 컷오프(Hz). 작을수록 정지 시 더 부드러움 |
| `--smooth-time` | 0.15 | 로봇 명령 ease-in/out 시간(초). 클수록 부드럽지만 반응이 느려짐 |
| `--max-speed` | 150 | 관절당 최대 각속도(도/초) 안전 상한 |
| `--fps` | 30 | 제어 주기 |
| `--lock-pan` / `--pan` | off / 0 | `shoulder_pan` 을 특정 각도에 고정 (수직 움직임만 쓸 때) |

* 처음엔 `--max-speed 60 --smooth-time 0.25` 로 느리고 안전하게 시작해서 점점 올려라.
* 첫 명령은 로봇의 **현재 자세**에서 출발하므로 시작할 때 튀지 않습니다.
* `arm_tracker.py` 의 `JOINT_LIMITS` 로 각 축 범위를 제한합니다. 처음엔 좁게 잡고 늘려라.

## 감도 튜닝

`arm_tracker.py` 의 `remap(...)` 입력 범위 숫자를 고치면 됩니다.
예를 들어 그리퍼가 너무 일찍 닫히면 `remap(pinch, 0.35, 1.6, ...)` 의 `0.35` 를 올립니다.
