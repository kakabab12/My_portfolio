### 발생한 문제와 해결

#### 문제 1 — `mp.solutions` 없음

```
AttributeError: module 'mediapipe' has no attribute 'solutions'
```

설치된 mediapipe 0.10.35에서 legacy `solutions` API가 제거됨.

→ **Tasks API로 전면 재작성.** `PoseLandmarker` / `HandLandmarker` 사용,
`.task` 모델 파일 별도 다운로드 (`download_models.py` 작성).

#### 문제 2 — 한글 경로에서 모델 로딩 실패

```
RuntimeError: Unable to open file at C:\Users\지용\...\pose_landmarker_lite.task, errno=-1
```

MediaPipe의 C++ 로더가 non-ASCII 경로를 열지 못함.

→ `model_asset_path` 대신 **파일을 바이트로 읽어 `model_asset_buffer`로 전달.**

#### 문제 3 — `cv2.imshow` 창이 안 뜸

```
cv2.error: The function is not implemented.
Rebuild the library with Windows, GTK+ 2.x or Cocoa support
```

`lerobot`이 `opencv-python-headless`를 함께 설치하는데, 이게 GUI 빌드를 가림.

→ headless 제거 후 **`opencv-contrib-python` 재설치.**
(이후 `pip check`가 "headless 없음"이라고 경고하지만 의도된 상태)

#### 문제 4 — 모터 6개 전부 무응답 ★ 가장 오래 걸린 문제

| 진단 항목 | 결과 |
| --- | --- |
| COM3 포트 열림 | 정상 |
| 보드 인식 (USB-Enhanced-SERIAL CH343) | 정상 |
| 프로토콜 0·1 × 보드레이트 6종 × ID 0~20 스캔 | **0개 발견** |
| 브로드캐스트 ping raw 전송 | **0바이트 응답** (에코조차 없음) |
| DTR/RTS 4가지 조합 시도 | 전부 무응답 |

→ **원인: 12V 전원 잭 접촉 불량.**

USB만 꽂아도 보드는 인식되고 빨간 LED도 켜지기 때문에 전원 문제인지 구분이 안 됐다.
잭을 다시 돌려 체결하니 6개 전부 즉시 인식 (ID 1~6, model 777 = STS3215, 1 Mbps).

> **판별법**: USB를 뽑은 상태에서 LED가 계속 켜져 있으면 12V 정상.
> 꺼지면 12V가 안 들어오는 것. **COM 포트 인식 여부는 판단 기준이 될 수 없다.**

## 오후 — 매핑 정교화

### 좌표계 문제 해결

| 문제 | 원인 | 해결 |
| --- | --- | --- |
| 몸통이 화면 밖이면 계산 불가 | 어깨–엉덩이 길이로 정규화 | **위팔 길이(어깨–팔꿈치)로 변경** |
| pan/lift가 서로 섞임 | 어깨 각도를 하나로 계산 | 좌우(x)·상하(y)로 **분리** |
| 좌우 방향 판별 불안정 | 하드코딩 | **반대쪽 어깨 위치로 자동 판별** |

### 방향 반전 문제 (반복 발생)

방향이 반대로 나오는 관절이 계속 나타났다. 매번 프로그램을 껐다 켜며 확인하는 게
비효율적이라 **실행 중 키보드로 즉시 반전**할 수 있게 개선.

| 관절 | 최종 상태 |
| --- | --- |
| `shoulder_pan` | 반전 필요 |
| `shoulder_lift` | 반전 필요 |
| `elbow_flex` | 정방향 |
| `wrist_flex` | 정방향 (부호있는 각도로 수정 후) |
| `gripper` | 정방향 |

**교훈 — 반전을 넣었다 뺐다 반복한 진짜 이유**

`wrist_flex`가 **부호 없는 각도**(0~180°)를 쓰고 있어서
위로 꺾으나 아래로 꺾으나 "구부러진 정도"만 나왔다.
방향 자체를 구분 못 하는 상태에서 반전을 켜니 계속 어긋났다.

→ **외적(cross product) 기반 부호 있는 각도**로 교체하니 해결.

또 하나 — 코드를 고쳐도 **이미 떠 있는 프로세스에는 반영되지 않는다.**
파이썬은 파일을 다시 읽지 않으므로 반드시 재시작해야 한다.
이것 때문에 "고쳤는데 그대로"인 상황이 여러 번 있었다.

### 1:1 각도 매핑으로 전환

"내가 45도 들면 로봇도 45도"가 목표. `remap`으로 범위를 늘려 잡던 걸 전부 실제 각도로 변경.

| 관절 | 이전 | 이후 |
| --- | --- | --- |
| `shoulder_lift` | 비율(sin값) → ±100 | `asin`으로 **실제 각도 복원** |
| `elbow_flex` | remap 압축 단위 | `180° − 안쪽각` |
| `wrist_flex` | remap ±80 → ±100 | 측정 각도 그대로 |
| `wrist_roll` | 손바닥 폭 비율 | 각도 기반 + 중립 오프셋 |

검증 (위팔 길이 고정, 각도만 변경):

| 실제 어깨 각도 | shoulder_lift 출력 |
| --- | --- |
| −90° | −90.0 |
| −45° | −45.0 |
| 0° | 0.0 |
| +45° | +45.0 |
| +90° | +90.0 |

#### 문제 — "팔을 다 펴도 로봇은 절반만 펴짐"

두 가지가 겹쳐 있었다.

1. `JOINT_LIMITS`가 ±100°로 자름 → 팔꿈치는 최대 150°까지 굽는데 잘려나감
2. 1:1 전환하면서 **0점이 100도 어긋남**
   → 로봇의 0도는 캘리브레이션 중간 위치인데, 사람의 "쭉 편 상태"를 0도로 계산

| 팔 상태 | 예전(정상 동작) | 1:1 전환 후 | 보정 적용 |
| --- | --- | --- | --- |
| 쭉 폄 | −100 | 0 ← 절반만 펴짐 | **−100** |
| 최대로 접음 | +100 | +150 ← 상한 박힘 | **+50** |

**진단 근거**: 모터 3번의 마지막 `Goal_Position`이 3867
= 정확히 상한 160°에 박혀 있었다. (모터 자체는 정상: ping OK, 온도 36°C, 에러 0)

→ `--elbow-offset` 기본값 −100, `JOINT_LIMITS` 확대 (`elbow_flex`: −110~160).

### 감도 문제

**"크게 움직여야만 반응함"** — 배율 문제인 줄 알았으나 실제 주범은
**1€ 필터가 느린 움직임을 잡음으로 판단해 눌러버린 것**이었다.

| 파라미터 | 이전 | 이후 | 효과 |
| --- | --- | --- | --- |
| `min-cutoff` | 1.0 | 2.5 | 느린 동작이 안 눌림 |
| `beta` | 0.4 | 0.6 | 빠른 동작 지연 감소 |
| `smooth-time` | 0.15 | 0.10 | 즉각 반응 |
| `max-speed` | 150 | 200 | 속도 상한 완화 |
| `gain` (신규) | — | 1.8 | 전체 배율 |

이후 **"많이 움직이되 빠르지 않게"** 요청으로 배율↑ / 속도↓ 재조정:
`max-speed` 90, `smooth-time` 0.22, `shoulder_lift` 배율 2.0, `elbow_flex` 2.5.

같은 60도 이동이 0.50초 → 1.00초로 느려짐 (이동량은 늘고 속도는 절반).

#### 포화(saturation) 문제

`shoulder_lift`에 오프셋 +35~50이 남아 있어 배율 2.0배와 겹치면
**팔을 38도만 올려도 상한 110°에 도달**. 그 이상 움직여도 반응 없음.

| 팔 각도 | 로봇 명령 |
| --- | --- |
| 0° | 35 |
| 15° | 65 |
| 30° | 95 |
| **38° 이상** | **110 (고정)** |

→ 배율과 전체 범위는 트레이드오프임을 수치로 제시하고 조정.
(로봇 가동범위 ±110°는 고정이므로, 배율을 올리면 반드시 그만큼 빨리 한계 도달)

### 실행 중 튜닝 시스템 구축

껐다 켜는 반복을 없애기 위해 키보드 조작 추가.

| 키 | 기능 |
| --- | --- |
| `1`~`6` | 관절 선택 |
| `[` / `]` | 선택 관절 0점 −5 / +5도 |
| `-` / `=` | 전체 배율 −0.2 / +0.2 |
| `,` / `.` | 선택 관절만 배율 조정 |
| `i` | 방향 반전 |
| `w` | **`tuning.json`에 저장** (다음 실행부터 자동 적용) |
| `p` | 현재 설정 출력 |
| `s` | 스냅샷 저장 |
| `q` / ESC | 종료 |

`tuning.json`은 임시 파일에 쓴 뒤 `os.replace`로 교체하여,
저장 중 중단돼도 기존 설정이 깨지지 않게 처리.

> **주의**: `tuning.json`이 명령줄 옵션보다 **우선**한다.
> CLI 기본값을 바꿔도 저장된 파일이 있으면 그쪽이 적용됨. (`--no-tuning`으로 무시 가능)

#### ★ 위험했던 순간

클론 시 Windows 긴 경로 제한으로 **체크아웃이 실패**.
그 상태로 커밋하면 git이 기존 파일을 전부 "삭제됨"으로 인식해
**레포의 다른 프로젝트가 통째로 삭제될 뻔했다.**

커밋 전 스테이징 내역을 확인하다 발견 → `core.longpaths` 활성화 후 작업 트리 복구.
최종 커밋은 **추가 5개, 삭제 0건**으로 검증 후 푸시.

> **교훈**: 클론 결과를 확인하지 않고 `git add` → `git commit` 하면 위험하다.
> 특히 체크아웃 실패는 조용히 넘어가므로 `git status`로 반드시 확인.
