# MediaPipe 팔 추적으로 SO-ARM-101 로봇팔 원격조종

웹캠 하나로 사람의 팔을 추적해서 SO-ARM-101 6축 로봇팔을 실시간으로 따라 움직이게 만든 프로젝틉니다.
별도 센서나 장갑 없이 **일반 웹캠의 2D 좌표(x, y)만** 사용합니다.

```
 [웹캠] --> MediaPipe Pose/Hand --> 관절각 계산 --> 필터링 --> lerobot --> SO-ARM-101
           (어깨/팔꿈치/손목/손가락)   (x, y 만)     (2단계)
```

## 무엇을 했나

| 단계 | 내용 |
| --- | --- |
| 1 | MediaPipe Tasks API 로 상체 + 손 랜드마크 추출 |
| 2 | 랜드마크의 x, y 좌표만으로 로봇 6축 관절각 계산 |
| 3 | 1€ Filter + SmoothDamp 2단계 필터링으로 떨림 제거 |
| 4 | lerobot 을 통해 SO-ARM-101(Feetech STS3215 × 6)에 각도 명령 전송 |
| 5 | 실행 중 키보드로 방향/0점/배율을 조정하고 파일로 저장 |

---

## 관절 매핑

사람의 관절 각도를 **실제 각도 그대로(1:1)** 로봇에 전달하는 것이 목표였습니다.
예를 들어 팔꿈치를 90도 굽히면 로봇도 90도 굽습니다.

| 로봇 관절 | 사람 동작 | 계산 방식 |
| --- | --- | --- |
| `shoulder_pan` | 팔 좌우 | 손목의 어깨 대비 x 오프셋 ÷ 위팔 길이 |
| `shoulder_lift` | 팔 위아래 | `asin((어깨y − 팔꿈치y) ÷ 위팔길이)` → 실제 각도 |
| `elbow_flex` | 팔꿈치 굽힘 | `180° − 위팔·아래팔 사잇각` (폄 = 0°, 최대 굽힘 = 150°) |
| `wrist_flex` | 손목 꺾기 | 아래팔 벡터 대비 손바닥 벡터의 **부호있는** 각도 |
| `wrist_roll` | 손 회전 | **고정** (아래 "한계" 참고) |
| `gripper` | 손 펴기/주먹 | 엄지끝 ↔ 나머지 4손가락끝 평균거리 ÷ 손바닥 길이 |

정규화 기준으로 **위팔 길이(어깨–팔꿈치)** 를 씁니다.
처음에는 몸통 길이(어깨–엉덩이)를 썼는데, 상반신만 화면에 잡히면 계산이 안 되는 문제가 있어서 바꿨습니다.
덕분에 카메라에 몸통이 안 나와도 동작하고, 카메라와의 거리가 변해도 값이 흔들리지 않습니다.

## 자연스러운 동작을 위한 2단계 필터링

랜드마크 좌표는 프레임마다 픽셀 단위로 떨립니다. 그대로 쓰면 로봇이 미세하게 파르르 떱니다.

### 1단계 — 1€ Filter (랜드마크 잡음 제거)

> Casiez, Roussel & Vogel, *"1€ Filter: A Simple Speed-based Low-pass Filter for Noisy Input in Interactive Systems"*, CHI 2012

속도에 따라 컷오프 주파수를 바꾸는 **적응형** 저역통과 필텁니다.

- 손이 멈춰 있을 때 → 강하게 눌러 떨림 제거
- 빠르게 움직일 때 → 컷오프를 올려 지연 감소

고정 계수 지수이동평균(EMA)은 "부드러움"과 "반응성" 중 하나를 포기해야 하는데, 이 필터는 자동으로 절충합니다.
실측 결과 정지 상태 잡음이 **표준편차 0.557 → 0.254** 로 줄면서도, 급격한 입력에는 거의 지연 없이 따라갔습니다.

### 2단계 — Critically-damped SmoothDamp (로봇 명령 평활화)

> Game Programming Gems 4 / Unity `Mathf.SmoothDamp` 와 동일한 공식

필터링된 목표값을 로봇에 곧바로 던지지 않고, 가속·감속이 이어지는 곡선을 그리며 따라갑니다.
목표를 지나쳐 진동하지 않도록 오버슈트 방지 로직이 들어 있습니다.

초기 구현은 "프레임당 고정 각도(`max-step`)" 방식이었는데,
프레임레이트가 흔들리면 실제 속도도 같이 흔들리는 문제가 있어서
**실제 경과시간(dt) 기준 `deg/s`** 로 바꿨습니다.

## 실행 중 튜닝 (키보드)

로봇 방향이나 0점을 맞추려고 매번 프로그램을 껐다 켜는 게 비효율적이라,
실행 중에 바로 조정하고 저장할 수 있게 만들었습니다.

| 키 | 기능 |
| --- | --- |
| `1`~`6` | 조정할 관절 선택 |
| `[` / `]` | 선택한 관절의 0점을 −5 / +5도 |
| `-` / `=` | 전체 동작 배율을 −0.2 / +0.2 |
| `i` | 선택한 관절의 방향 뒤집기 |
| `w` | 현재 설정을 `tuning.json` 에 저장 (다음 실행부터 자동 적용) |
| `p` | 현재 설정 출력 |
| `s` | 스냅샷 저장 |
| `q` / `ESC` | 종료 |

`tuning.json` 은 저장 중 중단돼도 기존 파일이 깨지지 않도록 임시 파일에 쓴 뒤 교체합니다.

## 설치 및 실행

### 요구사항

```
Python 3.11
mediapipe, opencv-contrib-python, lerobot[feetech]
```

> **주의**: `lerobot` 은 `opencv-python-headless` 를 함께 설치하는데,
> 이게 GUI 빌드를 가려서 `cv2.imshow` 창이 안 뜹니다.
> `opencv-contrib-python` 으로 교체해야 합니다.

### 모델 다운로드

```bash
python download_models.py
```

MediaPipe Tasks 모델(`pose_landmarker_lite.task`, `hand_landmarker.task`)을 `models/` 에 받습니다.

### 실행

```bash
# 로봇 없이 관절값만 화면으로 확인
python teleop_so101.py --dry-run

# 실제 로봇 구동
python teleop_so101.py --port COM3 --lock-pan
```

최초 1회는 lerobot 캘리브레이션이 실행된다 (각 관절을 손으로 끝까지 움직이는 대화형 절차).

## 주요 옵션

| 옵션 | 기본값 | 설명 |
| --- | --- | --- |
| `--gain` | 1.8 | 전체 동작 배율. 1.0 = 사람 각도와 1:1 |
| `--lock-pan` | off | 좌우 회전을 끄고 수직 움직임만 사용 |
| `--track-roll` | off | `wrist_roll` 추적 활성화 (기본은 고정) |
| `--invert` | "" | 방향이 반대인 관절을 콤마로 나열 |
| `--elbow-offset` | −100 | 팔꿈치 0점 보정 |
| `--min-cutoff` | 2.5 | 1€ 필터 최소 컷오프(Hz) |
| `--beta` | 0.6 | 1€ 필터 속도 계수 |
| `--smooth-time` | 0.10 | 명령 ease-in/out 시간(초) |
| `--max-speed` | 200 | 관절당 최대 각속도(도/초) |
| `--view side` | front | 측면 촬영 모드 |

## 겪은 문제와 해결

개발하면서 실제로 막혔던 지점들을 기록해둡니다.

### 1. 모터가 전혀 응답하지 않음

USB 시리얼 포트(COM3)는 정상 인식되는데 모터 6개가 전부 무응답이었습니다.
프로토콜 0·1 × 보드레이트 6종 × ID 0~20 전수 스캔에도 0개.
자기가 보낸 바이트의 에코조차 안 돌아왔습니다.

**원인**: 12V 전원 잭 접촉 불량.
USB만 꽂아도 보드는 인식되고 빨간 LED도 켜지기 때문에 전원 문제인지 구분이 안 됐습니다.
잭을 다시 체결하니 6개 전부 잡혔습니다.

> **판별법**: USB를 뽑은 상태에서 LED가 계속 켜져 있으면 12V 정상.

### 2. 한글 경로에서 MediaPipe 모델 로딩 실패

```
RuntimeError: Unable to open file at C:\Users\지용\...\pose_landmarker_lite.task, errno=-1
```

MediaPipe 의 C++ 로더가 non-ASCII 경로를 열지 못합니다.
**해결**: `model_asset_path` 대신 파일을 바이트로 읽어 `model_asset_buffer` 로 전달.

### 3. 손목을 위아래로 흔들어도 값이 안 변함

`wrist_flex` 계산에 **부호 없는** 사잇각(0~180°)을 쓰고 있었습니다.
위로 꺾으나 아래로 꺾으나 "구부러진 정도"만 나와서 방향 구분이 안 됐습니다.
**해결**: 외적(cross product) 기반 **부호 있는** 각도로 교체.

### 4. 손목을 90도 돌려도 반응 없음

`wrist_roll` 을 손바닥 가로폭 비율로 근사하고 있었는데,
90도 돌리면 폭이 0에 수렴하면서 **오히려 변화가 가장 안 보이는 지점**이 되는 결함이 있었습니다.
각도 기반으로 교체해 개선했지만, 근본적으로 xy 좌표만으로는 전완의 길이방향 회전축을 구할 수 없습니다.
실사용 가치가 낮아 **기본적으로 고정**하기로 했습니다.

### 5. 팔을 다 펴도 로봇은 절반만 펴짐

두 가지가 겹쳐 있었습니다.

- `elbow_flex` 만 아직 1:1 각도가 아니라 압축된 단위를 쓰고 있었습니다.
- `JOINT_LIMITS` 가 ±100°로 잘라내서, 최대 150°까지 굽는 팔꿈치가 잘려나갔습니다.

또한 1:1 로 바꾸면서 **0점이 100도 어긋났다**.
로봇의 0도는 캘리브레이션 때 잡은 중간 위치인데, 사람의 "쭉 편 상태"를 0도로 계산해버려서
로봇은 중간 위치(= 절반만 펴진 상태)에 머물렀습니다.

**진단 근거**: 모터 3번의 마지막 `Goal_Position` 이 3867 = 정확히 상한 160°에 박혀 있었습니다.
(모터 자체는 정상: ping OK, 온도 36°C, 에러 0)

**해결**: `--elbow-offset` 기본값을 −100 으로 설정.

### 6. 크게 움직여야만 로봇이 반응함

배율 문제인 줄 알았으나, 실제 주범은 **1€ 필터가 느린 움직임을 잡음으로 판단해 눌러버린 것**이었습니다.
`min_cutoff=1.0` 에서는 천천히 움직이면 신호가 거의 사라집니다.

**해결**: `min_cutoff` 1.0 → 2.5, `beta` 0.4 → 0.6 으로 올리고,
`smooth_time` 0.15 → 0.10, `max_speed` 150 → 200 으로 반응성을 높였습니다.
추가로 전체 배율 `--gain` (기본 1.8) 을 도입했습니다.

## 한계

- **`wrist_roll` 은 원리적으로 구할 수 없습니다.** 2D 이미지 평면에서는 전완의 길이방향 회전을
  직접 관측할 수 없습니다. 제대로 하려면 카메라 2대 또는 depth 센서가 필요합니다.
- **측면 촬영(`--view side`) 에서는 `shoulder_pan` 을 구할 수 없습니다.** 좌우 정보가 화면에 없습니다.
  대신 팔이 움직이는 시상면이 카메라와 나란해져 어깨·팔꿈치 각도는 더 정확해집니다.
- **가려짐에 취약합니다.** 팔이 몸통에 겹치면 추적이 튑니다. 카메라와 가까운 쪽 팔을 쓰는 게 좋습니다.
