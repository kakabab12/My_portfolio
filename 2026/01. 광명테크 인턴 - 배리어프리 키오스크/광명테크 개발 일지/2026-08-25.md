# 2026-08-25 (화) 개발일지

"현장에 놓을 수 있는 상태"를 목표로 전면 점검했습니다. 무인 키오스크는 옆에
사람이 없으니, **조용히 멈추는 것**이 가장 나쁜 실패입니다. 그 관점으로 코드를
다시 훑었습니다.

---

## 1. 드래그 중 종료하면 마우스 버튼이 눌린 채 남던 문제 ★가장 심각

**증상** — 입을 벌려 드래그하는 중에 프로그램이 꺼지면 왼쪽 버튼이 **OS
수준에서 계속 눌린 상태**로 남습니다. 바탕화면 전체가 드래그 상태가 되어
아이콘이 딸려다니고 모든 클릭이 영역 선택이 됩니다. 재부팅 말고는 손쓸 방법이
없습니다.

재현으로 확인:
```
종료 후 마우스 기록: ['PRESS']     ← release 가 없다
```

**같은 원인으로 두 번째 경로도 있었습니다.** 드래그 중에 `p`로 실제 제어를 끄면,
입을 다물어도 버튼이 안 풀립니다. 떼는 코드에 "제어가 켜져 있을 때만"이라는
조건이 걸려 있었기 때문입니다.

**고친 것** — 판단 기준을 **"제어가 켜져 있는가"가 아니라 "우리가 실제로
눌렀는가"**로 바꿨습니다. 눌렀으면 무슨 일이 있어도 뗍니다. 종료 안전장치(예외·
Ctrl+C·콘솔 닫기)에도 화살표 복구와 함께 묶었습니다.

> 확인: 세 경로(정상 종료 / p 토글 / 예외로 죽음) × 두 파일 모두 버튼 풀림
> 38초 반복 드래그에서 press 7회 / release 7회, 순서 위반 없음

## 2. 카메라 드라이버가 예외를 던지면 조용히 정지하던 문제

**원인** — 자동 복구는 카메라 읽기가 **실패를 돌려줄 때만** 작동합니다.
**예외를 던지면** 캡처 스레드가 통째로 죽는데, 복구는 그 스레드가 돌아야
작동하므로 영영 돌지 않습니다.

죽은 뒤에도 **예외가 안 난다** — 마지막 프레임이 계속 반환되어, 화면상으론
얼굴이 얼어붙은 채 커서만 안 움직입니다. 무인 키오스크에서 가장 나쁜 실패
방식입니다.

```
고치기 전:  스레드 죽음, 프레임 번호 20에서 영구 정지
고친 뒤:    4초간 고장 -> 스스로 복구 -> 30fps 정상
```

## 3. 로그가 디스크를 채우던 문제

세 가지가 맞물려 있었습니다.

```
카메라 빠짐 → 매 프레임 실패 → 오류 기록 초당 20건
             → 로그 회전 없음 → 디스크 참 → 키오스크 정지
```

- **로그 회전 추가** — 파일 하나 5MB, 최대 4개 → 전체 **20MB 상한**
- **오류 반복 기록 제한** — 같은 오류는 처음 한 번만 자세히, 이후 30초마다
  "몇 번째 반복 중"만

> 실측: 카메라 고장 40초 = 실패 약 1,200회 → **로그 2줄**

**한 번 잘못 고쳤습니다.** "복구 성공하면 시계 초기화"를 넣었는데, 장치는 다시
열리는데 곧바로 또 실패하는 깜빡임이 **바로 그 폭주의 정체**라 제한이
무력해졌다(초당 2줄 그대로). 그 초기화를 뺐습니다.

## 4. 감시 장치 추가

**왜** — 추론이 멈춰도 아무도 모릅니다. 화면은 떠 있고 커서만 반응하지 않으면,
앞에 선 분은 자기가 잘못한 줄 알고 몇 번 더 해보다 그냥 돌아갑니다.

**두 가지를 따로 본다** — 원인이 다르면 할 일도 다르기 때문입니다.

| 증상 | 화면 표시 |
|---|---|
| 추론 루프가 안 돎 | 프로그램에 문제가 생겼습니다 - 관리자에게 알려주세요 |
| 루프는 도는데 새 프레임이 없음 | 카메라 신호가 없습니다 - 연결을 확인해주세요 |

```
09:04:32 [ERROR]   감시: 카메라 신호가 없습니다
09:04:36 [WARNING] 감시: 정상으로 돌아왔습니다
```

## 5. 출력이 막히면 프로그램이 멈추던 문제

매 프레임 커서 좌표를 찍는데, **다른 프로그램이 출력을 파이프로 받아가면서
읽지 않으면** 그 다음 출력이 영영 반환되지 않습니다. 추론 스레드가 거기서
멈춰 얼굴 인식이 통째로 정지합니다.

> 실측: 아무도 읽지 않는 파이프에 연결하니 **8.2초 / 240줄** 만에 완전 정지

**고친 것** — 출력 전담 스레드를 두고, 본 스레드는 큐에 넣기만 합니다. 큐가
차면 버린다 — 막히느니 몇 줄 잃는 게 낫습니다.

> 확인: 출력이 완전히 막힌 45초 동안 추론 **1,021회** 계속 돎

## 6. 한글 인코딩 크래시 — 시작하자마자 죽던 문제

줄표(`—`)가 한글 윈도우 기본 인코딩(cp949)에 없어서, 찍으려는 순간
`UnicodeEncodeError`로 죽습니다. **exe만이 아니라 소스로 그냥 실행해도** 죽었습니다.

내 시험이 전부 `-X utf8`이라 이걸 계속 가리고 있었습니다. 현장에서 그냥 실행하면
죽는데 개발 중에는 안 보이는, 가장 나쁜 종류의 차이였습니다.

**더 나빴던 것** — 설치하는 사람을 도우려고 만든 자가 점검이, 정작 문제를
발견한 그 순간에 죽고 있었다(안내 메시지에 줄표가 들어 있어서).

**고친 것** — 출력이 콘솔이 아니면 UTF-8로 못박고, 어느 경우든 못 찍는 글자는
`?`로 바꿉니다. 글자 하나 때문에 트래커가 죽는 일은 이제 없습니다.

## 7. 그 밖에

- **시작 전 자가 점검 신설** — 설정·모델·카메라를 한 번에 보고 무엇이
  잘못됐고 어떻게 고치는지 알려줍니다. `--check` 로 실행
- **버전 정보 로깅** — 현장 연락을 받았을 때 어느 빌드인지 알 수 있게
- **자가 점검 결과가 로그에 안 남던 문제** — 로그 초기화가 점검보다 뒤에
  있었습니다. 점검 실패야말로 나중에 로그로 봐야 할 일인데 그것만 안 남았습니다
- **콘솔 없이 실행하면 명령 스레드가 조용히 죽던 문제** — `pythonw`나
  서비스로 띄우면 `quit` 명령이 영영 안 먹었습니다
- **종료 시 스레드가 살아있는데 모델 해제하던 문제** — 방어 코드 추가

## 확인한 것 (문제 없었음)

의심했다가 측정으로 기각한 것들.

- **화면 배율(DPI)** — 이 PC는 125%라 코드가 화면을 1536×864로 아는데 실제는
  1920×1080. 커서가 오른쪽 20%에 도달 못 할 것처럼 보였지만, 윈도우가 좌표를
  자동 변환한다(1535 → 1919 정상 도달)
- **이상한 얼굴 좌표** — 눈 사이 거리 0, NaN, 무한대, 1e9 점프를 주입해도
  안 죽고 다음 프레임에 정상 복귀
- **렌더 속도** — 목표 30fps 대비 실측 29.7fps. `timeBeginPeriod`는 효과 없음
- **exe 재빌드** — 열어보니 **얇은 런처**라 옆에 있는 소스를 그대로 실행합니다.
  8/18 빌드 exe로도 오늘 고친 코드가 그대로 돌아갑니다. 재빌드 불필요

현장에선 죽는" 버그를 만들었습니다. 시험은 실제 실행 방식 그대로 해야 합니다.
