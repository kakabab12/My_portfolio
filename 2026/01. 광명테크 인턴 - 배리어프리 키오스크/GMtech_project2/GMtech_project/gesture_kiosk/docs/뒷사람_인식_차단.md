# 다중 이용 환경 조작권 보호 — 뒷사람·옆사람 오인식 차단

작성 2026-08-11 · 배리어 프리 제스처 키오스크 · `feat/hand_bend` 브랜치

---

## 1. 문제

비접촉 제스처로 조작하는 배리어 프리 키오스크를 동사무소·법원 등
**다중 이용 공공기관**에 설치합니다. 실사용 테스트에서 대기줄에 선 다른
사람에게 조작 권한이 넘어가는 문제가 발생했습니다.

- 사용자 뒤에 사람이 서면 그 손이 인식되어 조작권이 넘어감
- 옆에 사람이 서 있어도 같은 문제 발생
- 공공기관 민원 화면에서 조작권 탈취는 단순 불편이 아니라
  **개인정보·업무 중단 문제**

---

## 2. 왜 처음 시도들은 실패했는가

초기 대응은 전부 **화면상 2D 위치**를 기준으로 다른 사람을 걸러내려 했습니다.

| 시도한 방법 | 실패 이유 |
|---|---|
| 사용자 주변 반경 제한 | 대기줄은 일렬로 서서 화면에서 앞사람과 겹침 — 위치로 구분 불가 |
| 손목 위치 비교 | 포즈 손목 관측이 자주 붕괴(실측 어깨폭 12~21px로 무너지는 프레임 존재) |
| 옷 색상(외형) 비교 | 테스트 인원이 모두 어두운 상의라 다른 사람을 같은 사람으로 오판 — 오히려 하이재킹을 가속 |
| 배경 흐림(사각형) | 팔 도달을 다 담으려면 상자가 커져야 하는데, 그 안에 다른 사람이 통째로 들어옴 |

**공통 원인**: 대기줄은 카메라 2D 투영에서 사용자와 겹쳐 보입니다.
겹친 두 대상을 위치 정보만으로 구분하는 것은 원리적으로 불가능합니다
(다중 객체 추적 분야의 "ID Switch" 문제와 동일 — 순수 기하 정보만으로는
겹침·교차에서 구조적으로 실패한다는 것이 알려져 있음).

## 3. 핵심 발견 — 빠져 있던 축: 거리

2D 위치로 못 가르는 문제는 **카메라와의 거리**로는 가를 수 있습니다.
뒷사람은 사용자보다 항상 더 멀리 있기 때문입니다.

### 3-1. 새 센서 없이 거리를 얻는 법

사용하던 손 인식 라이브러리(MediaPipe)가 손마다 두 종류의 좌표를 제공합니다.

- **화면 좌표**(px) — 카메라에 찍힌 크기, 거리에 따라 달라짐
- **월드 좌표**(m) — 손의 실제 물리적 크기, 거리와 무관하게 고정

두 값의 비율을 계산하면:

```
화면 크기(px) ÷ 실제 크기(m) = 초점거리 ÷ 거리
```

**손의 실제 크기가 약분되어 사라지고, 순수한 거리 정보만 남습니다.**
이미 자(尺)로만 쓰이던 값을 거리계로 재해석한 것 — 새 모델, 새 센서,
추가 의존성 없이 거리 축을 확보했습니다.

### 3-2. 실측 검증

배포 직후 실기 로그에서 이 값을 측정한 결과, 뚜렷한 **이봉분포**가
나타났습니다.

```
사용자 본인 손 (통과) : 1.07 ~ 1.76
뒤에 선 사람 손 (거부) : 0.51 ~ 0.78
```

**0.78과 1.07 사이 구간이 완전히 비어 있습니다.** 같은 사람의 관측
노이즈라면 값이 연속적으로 흩어져야 하는데, 명확히 두 무리로
갈렸다 — 물리적으로 다른 두 거리를 실제로 측정하고 있다는 직접 증거.

## 4. 최종 방어 구조

### 4-1. 뒷사람 차단 (거리 기반)

| 방어층 | 역할 | 현재값 |
|---|---|---|
| 깊이 관문 (절대) | 손 깊이 ÷ 앵커 어깨너비가 기준 미만이면 거부 | 0.80 |
| 깊이 관문 (상대) | 손 깊이 ÷ 최근접 손 깊이가 기준 미만이면 거부 | 0.70 |
| 작동 거리 창 | 카메라 기준 절대 거리 하한 — 앵커 관측이 붕괴해도 살아있음 | 300px (현장 재보정 필수) |
| 대기줄 이음 방어 | 사용자 식별(앵커)이 일렬로 선 뒷사람으로 넘어가지 않도록 방지 | 0.80 |
| 관측 중앙값 필터 | 순간적인 관측 오류(스파이크)를 판정에 반영하지 않음 | 표본 3개 |

**배치 원칙**: 거리 관문은 반드시 "추적 중인 손은 위치 판정을 면제한다"는
규칙보다 **앞**에 둡니다. 그렇지 않으면 뒷사람 손이 한 번이라도 인식에
들어오는 순간 위치 판정을 영구히 면제받아 쫓아낼 수 없게 된다 —
"한번 뺏기면 안 돌아온다" 현상의 구조적 원인이었습니다.

### 4-2. 옆사람 차단 (거리로 안 풀리는 문제)

옆에 선 사람은 **카메라와의 거리가 사용자와 거의 같다** — 뒷사람과
정반대 기하이므로 거리 관문이 원리적으로 듣지 않습니다.

해법은 이 프로젝트가 이미 다른 곳에서 쓰던 원리를 재사용했다:
**판정 영역이 사용자의 팔을 따라다니게 합니다.** 화면 전체나 몸통
전체가 아니라, 사용자의 어깨·팔꿈치·손목 주변만 선명하게 남긴다 —
팔을 내리면 옆 사람이 서 있는 자리는 자동으로 범위 밖이 됩니다.

### 4-3. 화면 표시(배경 흐림) — 보조 방어선

인식 대상이 아닌 사람을 화면에서도 흐리게 표시하는 기능. 사람별
실루엣(세그멘테이션) 마스크를 이용하며, 아래 안전장치를 겹쳤습니다.

- **연결 성분 분석**: 사용자 몸과 픽셀이 이어지지 않은 덩어리는
  무슨 일이 있어도 선명하게 남지 않음(위상 기반 보장)
- **타인 실루엣 명시적 제외**: 마스크가 겹치는 애매한 구간은
  흐리는 쪽으로 판정
- **1인 제한 상자·팔 반경 제한**: 정밀 마스크가 오작동해도 넘지
  못하는 상한선

⚠ 이 기능은 실제 고객이 보는 화면에는 영향이 없다(고객용 프로그램은
이벤트만 수신하고 영상을 표시하지 않음) — 개발/점검용 디버그 화면의
가시성 개선 목적.

## 5. 성능

블러 처리 도입 초기 구현이 프레임당 58ms로 과도하게 느렸던 것을
발견하여 최적화했습니다.

```
초기 구현       : 58.0 ms/프레임
최적화 후       :  9.7 ms/프레임   (약 6배)
```

원인은 대용량 배열에 대한 비효율적인 인덱싱 연산이었으며, 영상처리
라이브러리(OpenCV)의 최적화된 연산으로 대체해 해결했습니다.

## 6. 부작용과 교훈 — 방어를 추가할 때마다 자기 손을 자를 뻔했다

방어층을 쌓는 과정에서 **세 차례** 사용자 본인의 손이 잘못 차단되는
사고가 있었습니다. 매번 실측 로그로 원인을 확인하고 즉시 수정했습니다.

1. **체형 학습 기능의 결함**: 사용자 체형에 맞춰 임계값을 자동
   학습시키려 했으나, "팔을 뻗으면 손이 가까워진다"는 사실을 놓쳐
   팔을 굽히는 순간 본인 손이 잘리는 결함 발견 → 제거
2. **정체성 추적 반경의 결함**: 손의 화면 크기를 정체성 추적 반경의
   기준으로 썼는데, **주먹을 쥐면 손이 화면에서 작아져 추적 반경도
   함께 줄어드는** 현상을 발견. 특정 손동작(주먹 계열 제스처)에서
   추적이 끊기거나 다른 사람에게 옮겨가는 원인이었음 → 손 모양과
   무관한 별도의 자(尺)로 교체. 같은 결함이 제스처 판정 모듈에도
   퍼져 있어 함께 수정
3. **손실 표시 처리 시간의 방향 오류**: 화면이 깜빡이는 문제를
   해결하려 유지 시간을 늘렸으나, 재검토 결과 사용자가 움직이는
   중에는 오히려 **낡은 위치 정보로 현재 손을 가리는** 역효과가
   더 크다고 판단해 방향을 수정

**원칙**: 부작용이 실측으로 확정된 기능은 비활성화(끄기)가 아니라
완전히 삭제합니다. 꺼진 채 남겨두면 나중에 "왜 안 쓰이지"라는 이유로
되살아나 같은 사고를 반복시킬 위험이 있습니다.

## 8. 남은 한계

1. **바로 뒤(수십 cm) 밀착**: 깊이 차이가 거의 없어 어떤 방법으로도
   구분이 어려운 물리적 한계 구간. 운영상 바닥에 대기선(권장 1m
   이상 이격)을 표시하는 것이 근본적인 보완책
2. **현장 재보정 필수**: 작동 거리 창(300px)은 개발 환경 기준값 —
   실제 설치 거리·카메라 사양에 맞춰 현장에서 재측정 필요. 특히
   **휠체어 사용자는 착석 자세로 거리·높이가 달라지므로 별도 확인
   필요**(배리어 프리 요건)
3. **IR 카메라 전환 시 전체 재검증 필요**: 현재 임계값은 모두 RGB
   카메라 실측 기준
