## 2. 2주차 (2026-07-13 ~ 2026-07-16) — 동작 체계 대규모 재설계

이 주에 **동작 체계가 하루에도 여러 번 바뀔 만큼 격렬한 반복 개선**이 있었습니다.
대부분 "실기(맥/웹캠) 테스트 → 사용자가 오탐/미탐 보고 → 즉시 수정" 사이클.

### 큰 방향 전환 (7/15)
- **팔 스윙(쓸기) 체계로 전환**: 좌/우 쓸기=포커스 이동, 아래=이전 화면(go_back
  신설), 위=처음으로 — 포즈 손목 궤적 기반이라 손가락이 없어도 조작 가능
- 선택(확인)은 처음엔 "손등/팔등 보이기"로 설계했다가, 같은 날 **고개 꾸벅 2회**로
  재확정(더 직관적, 팔이 없어도 가능) — 목 길이 비율(코~어깨, 어깨너비 정규화)로 판정
- 이 과정에서 손 검출 경로(MediaPipe 손 랜드마크, 팔등 CNN 분류기, 데이터 수집·학습
  스크립트)를 전면 제거 — **포즈(RTMPose) 단일 엔진**으로 단순화
- 구 동작 체계(주먹→펴기, OK 핀치, 양손바닥 10초, HaGRID ONNX 엔진) 전부 제거

### 실기 피드백 기반 반복 수정 (7/16, 하루에 10건 이상 커밋)
사용자가 매번 실기로 테스트하고 문제를 보고 → 즉시 수정하는 패턴이 반복됨:
1. **팔꿈치 폴백** — 손목 인식이 안 되는 경우 팔꿈치 궤적으로 대체 판정
2. **쓸기 정지 재장전** — 손을 원위치로 되돌리는 동작이 반대방향 쓸기로 오인되는
   문제 → 이벤트 후 잠깐 멈춰야 재장전되도록 수정
3. **한 번에 한 팔만 인식** — 양팔을 동시에 추적하니 쉬는 팔의 잡음이 간섭 → 더 높이
   든 팔만 활성화
4. **어깨너비 정규화** — 카메라 위치·거리에 따라 인식률이 들쭉날쭉 → 임계값 단위를
   "자기 어깨너비의 몇 배 움직였나"로 전환(거리 불변)
5. **주민등록증 OCR 기능 전면 제거** — "제스처에 집중하자"는 사용자 결정. 개인정보
   처리 이슈(회사 확인 필요 №11 항목)도 이 시점에 자동 소멸
6. **판정 계기판 신설** — 임계값·진행도 등 내부 판정값을 화면에 노출, 이후 튜닝은
   추측이 아니라 실측 수치 근거로 진행하는 방식이 이때부터 자리잡음
7. **토크백 문법 정렬, 정지 재장전 제거→반대방향 삼킴, 확인/선택 통합, 동작 배치
   정정(처음으로=아래 2연속), 복귀 판정 위치 기반 전환** 등 세부 튜닝 다수

이 주 끝 기준 단위 테스트 37건, 동작 체계는 "쓸기 이동 + 고개 꾸벅 선택 + 아래
1회=이전/아래 2연속=처음으로" 형태로 정리됨.

## 3. 3주차 전반 (2026-07-18 ~ 2026-07-21) — 헤드트래커로 전면 전환

### 결정적 전환점 (7/18)
2주차까지 쌓아온 **팔 스윙(포즈) 체계를 통째로 폐기**하고, `head_tracker_manual.md`를
근거로 **MediaPipe FaceLandmarker(얼굴 랜드마크+블렌드셰이프) 기반 헤드트래커**로
전면 재설계:

| 기능 | 판정 기준 |
|---|---|
| 포인터 이동 | 코끝(랜드마크) 위치 추적 |
| 선택/확인 | 입 벌리기 즉시, 또는 1.5초 응시(dwell) |
| 뒤로가기/처음으로 | (최초) 눈썹 올리기 → (2차) 입 오므리기 → (3차, 최종) 양 눈 감고 0.6초 |
| 커서 재정렬 | (최초) 볼 부풀리기 → (2차) 코 찡그리기 → (3차, 최종) 입 오므리기 |

- 블렌드셰이프(jawOpen·eyeBlink·mouthPucker 등)는 MediaPipe가 이미 0~1로
  정규화·학습해 내보내는 신호라 얼굴 형태·거리 편차에 강건 — 랜드마크 거리비를
  직접 계산할 필요가 없어짐
- **GPU/CUDA 스택 전면 제거** (onnxruntime-gpu·torch CUDA DLL 등록·rtmlib 삭제) —
  MediaPipe FaceLandmarker는 CPU만으로 23~30 FPS가 나와(실측) GPU 자체가 불필요해짐.
  이전 RTMPose는 CPU 0.5 FPS라 GPU가 필수였던 것과 대비되며, 이 세션 초반 내내
  씨름했던 "NVIDIA MX250(Pascal)이 최신 onnxruntime-gpu와 근본 비호환" 문제 자체가
  통째로 사라짐
- 이벤트 스키마 축소: `[move_left, move_right, select, go_back, go_home]` →
  `[select, go_back]`(이후 recenter 추가로 3종)
- `demo_ui`를 선형 포커스(토크백식)에서 **커서 호버 기반 선택**으로 전면 개편,
  `person_lock`에 `lock_generation` 카운터 신설(재잠금 시 커서 캘리브레이션 재실행 트리거)

### 실기 튜닝과 사용자 피드백 대응 (7/18~7/21)
- 민감도 튜닝(고개를 조금만 움직여도 커서가 화면 끝까지 튀는 문제),
  캘리브레이션 **평균→중앙값** 전환(과도기 프레임 1~2장에 기준점이 끌려가 커서가
  화면 상단에 눌러붙던 버그 해결)

  주세요") — 반응이 없을 때 이유를 화면만 보고 알 수 있게
- 판정을 **고정 임계값 → "잠금 직후 평상시 기준선 + 여유값"**으로 전환 — 사람마다
  평상시 eyeBlink 값이 0.1~0.6까지 편차가 커서 고정 임계 하나로는 오탐/미탐이 갈림
- **뒤로가기를 단계별 이동으로 변경** — 기존엔 항상 처음(home)으로 가서 주민등록번호를
  다 입력하고 실수로 뒤로가면 전부 날아갔음. 이제 한 단계씩만 이동 + 입력값 보존
- 데모 UI에 **주민등록번호 입력 키패드**, **발급 장수 선택 화면** 신설 — 입력값은
  브라우저 안에만 머물고 엔진으로는 전달되지 않음("엔진은 개인정보를 다루지 않는다"
  원칙 유지)
- **TTS 간헐적 무음 버그 수정** — 음성 안내 워커 스레드가 COM(SAPI) 아파트를
  초기화하지 않아 pyttsx3 초기화가 실행마다 성공/실패가 갈렸음. `pythoncom.CoInitialize()`
  추가로 해결
- **커서 재정렬 제스처 3차례 교체** (사용자 실기 리포트에 따른 연속 대응):
  볼 부풀리기(cheekPuff, 거의 인식 안 됨) → 코 찡그리기(noseSneer, 역시 인식 안 됨)
  → **입 오므리기(mouthPucker, 최종)**. 두 번 연속 잘못 고른 것을 계기로 전체
  블렌드셰이프 원점수(52개)를 계기판에 노출해, 이후로는 추측이 아니라 실측값으로
  후보를 고르는 방식으로 전환
- 발급 확인 화면 "취소" 버튼이 "발급하기"보다 좁게 그려지던 CSS 버그 수정

### 실기 피드백 기반 3차 재조정 (커밋 전, 실기 카메라로 직접 검증 불가한 환경이라
사용자 리포트에 의존해 순차 대응)
1. 입 오므리기(recenter) 미탐 잦음 → 확정 임계값을 기준선 대비 0.43 → **0.20**으로
   대폭 완화
2. 아이트래킹 좌우는 잘 되는데 상하가 둔감 → 민감도 2.0→5.0→9.0까지 계속 올려봄
3. 그래도 상하가 안 움직이고 오히려 심하게 떨린다는 리포트 → **배율 문제가 아니라
   상하 신호 자체의 검출 잡음이 크다**고 결론, 전략 전환: 민감도는 좌우와 같은
   중립값(7.0)으로 되돌리고 **x/y축 평활(smoothing)을 분리**해 상하만 훨씬 강하게
   걸어 떨림을 누르는 방식으로 재설계 (`smoothing_alpha_x`/`smoothing_alpha_y`)
