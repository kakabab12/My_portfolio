# 배리어프리 키오스크 입력 방식 개발 — 중간보고서

작성일: 2026-08-03 · 작성자: 인턴 이지용 · 대상 기간: 2026-07-06 ~ 2026-08-03
※ 날짜순으로 정리했습니다. 헤드트래커 트랙만 다루며, 손 제스처는 별도 트랙이라
이 보고서 범위에서는 제외했습니다.

## 1. 개요

터치 없이 카메라 하나로 조작하는 무인 민원발급기 입력 방식을 개발 중이며,
이 보고서는 그중 **헤드트래커(얼굴 인식 기반 입력)** 트랙의 진행 경과를
다룹니다.

## 3. 3주차 (2026-07-18 ~ 2026-07-22) — 헤드트래커 전면 전환·이식 [핵심]

### 7/18 — 헤드트래커 도입 (가장 큰 전환점)

기존 입력 판정 방식은 GPU 의존, 구형 GPU와 최신 CUDA 버전 간 호환성 문제
등 성능·안정성 한계가 뚜렷해 근본적인 재검토가 필요했습니다.

`head_tracker_manual.md`를 근거로 **MediaPipe FaceLandmarker(얼굴 랜드마크 +
블렌드셰이프) 기반 헤드트래커**로 전면 재설계했습니다:

| 기능 | 판정 기준 |
|---|---|
| 포인터 이동 | 코끝 위치 추적 |
| 선택/확인 | 입 벌리기 즉시, 또는 1.5초 응시 |
| 처음으로/뒤로가기 | 양 눈 감고 0.6초 유지 |
| 커서 재정렬 | 입 오므리기 |

블렌드셰이프는 MediaPipe가 이미 0~1로 정규화해 내보내는 신호라 얼굴 형태나
거리 편차에 흔들리지 않습니다. 이 전환 덕분에 **GPU/CUDA 의존이 완전히
사라져**(CPU만으로 23~30 FPS 실측) 그동안 골치 아팠던 GPU 버전 호환성
문제까지 함께 해결됐습니다. 같은 날 커서가 화면 위쪽에 눌러붙던 버그도
고치고, 캠 화면과 메뉴 오버레이를 하나로 합쳤으며, 주민등록번호 입력
키패드와 발급 장수 선택 화면도 새로 만들었습니다.

### 7/20 — 성능·정렬 개선

- 추론 FPS 30 달성(KPI) — 처리 해상도 축소(640x360), 프로세스 우선순위 상향 등
- 카메라 화면비 정렬 버그 수정 — 커서·호버 판정이 가장자리에서 최대 12.5%까지
  어긋나던 문제였습니다
- 접근성 상태 안내 오버레이 신설("카메라 앞에 서 주세요" 등), 뒤로가기를
  단계별 이동으로 변경(입력값 보존)

### 7/21 — 안정화

- **음성 안내(TTS) 간헐적 무음 버그 수정** (COM 초기화 누락)
- **커서 재정렬 제스처를 3차례 교체**: 볼 부풀리기(cheekPuff) → 코
  찡그리기(noseSneer) → **입 오므리기(mouthPucker, 최종)** 순으로 바꿨습니다.
  앞의 두 제스처는 실기에서 거의 인식되지 않아 교체했고, 이후로는 전체
  블렌드셰이프 원점수를 계기판에 노출해 추측이 아니라 실측값을 보고 후보를
  고르도록 개선했습니다
- 판정 방식을 고정 임계값에서 "잠금 직후 평상시 기준선 + 여유값" 방식으로
  바꾸고, "취소" 버튼 CSS 비율 버그도 수정했습니다

### 7/22 — 라즈베리파이5 이식 및 저장소 정리

- 라즈베리파이5로 이식했습니다 — 카메라 듀얼 백엔드(v4l2/picamera2), 리눅스
  프로세스 우선순위 설정 등을 진행했고, Python 버전이 예상과 달라 pyenv로
  3.11.5를 고정했으며, mediapipe 최신 버전이 라즈베리파이(aarch64) 휠을
  지원하지 않아 호환 버전으로 다운그레이드했습니다
- MediaPipe FaceLandmarker 라이선스(Apache-2.0)를 확인했습니다
- 저장소 구조를 개편해 win.ver·rpi.ver 프로젝트를 하나의 저장소로
  통합했습니다

## 4. 3주차 이후 (2026-07-22 ~ 2026-08-03)

### 7/22~7/23 — 아이트래킹(시선) 모드 신설 → 폐기

기존 코끝 기준은 그대로 두고, **양쪽 눈 시선(홍채-눈꺼풀 상대위치)** 기반
커서 모드에 한번 도전해보고 싶어서 추가했습니다. 버튼으로 실행 중에 전환할
수 있게 했고, 실기 카메라가 없는 환경이라 사용자 리포트를 받아가며
순차적으로 재조정했습니다:

1. 재정렬(입 오므리기) 미탐이 잦음 → 확정 임계값 완화
2. 시선의 상하 움직임이 둔감함 → 민감도를 계속 올려봄
3. 그래도 안 움직이고 오히려 심하게 떨림 → **민감도가 아니라 신호 자체의
   잡음이 문제**라고 판단, 배율을 올리는 대신 **상하축 평활(smoothing)만
   따로 강하게** 거는 방식으로 전략을 바꿈

→ **결국 폐기했습니다.** 좌우 움직임은 쓸 만한 수준까지 왔지만 상하
움직임이 끝내 더뎌 실사용은 어렵다고 판단했습니다. 시선 모드는 접고,
코끝 기준 커서로 계속 진행하고 있습니다.

### 7/23 — 특허 조사

관련 액션 아이템("특허 확인 — 회사 존속 리스크")에 대응해 카메라 기반
헤드트래커·시선추적 특허와 관련 표준(ISO/IEC 30113, ISO 9241-960, 국내
배리어프리 키오스크 인증기준)을 조사했습니다. 대부분 권리가 소멸된
상태였지만, **활성 특허 1건**(눈·머리·표정을 결합해 제어하는 미국 특허,
만료 2034)이 현재 헤드트래커/아이트래킹 모드 구조와 개념적으로 가까워
**변리사 정밀 검토가 필요한 최우선 대상**으로 표시했습니다. (참고용
조사이며 법적 효력은 없습니다)

### 7/30 — 커서 재정렬 교체·헤드트래커 모드 병합

- **커서 재정렬 방식 교체(입 오므리기 → 응시)**: 7/21에 "최종"으로 정했던
  입 오므리기(mouthPucker) 재정렬이 실사용에서 오탐이 너무 잦았습니다 —
  오므리지 않아도 자주 확정돼 버렸습니다. 임계값을 완화해 봐도 해결되지
  않아 **응시(dwell) 방식으로 교체했습니다**: 커서가 화면상 일정 반경
  안에 일정 시간 머무르면 재정렬이 확정되는 방식입니다. 입 오므리기 판정
  로직은 나중에 다시 쓸 수도 있어 지우지 않고, 기본값만 비활성으로
  바꿔뒀습니다.
- **헤드트래커 모드를 손 제스처 트랙에 병합**: 손 제스처는 그대로 두고,
  머리를 좌우로 흔들면 헤드트래커 모드로 전환되는 두 번째 입력 경로를
  추가했습니다(기존 헤드트래커 프로토타입에서 이식, 아이트래킹 모드는
  제외). 고개 끄덕임과 헷갈리지 않도록 좌우 흔들림이 상하 움직임보다
  뚜렷할 때만, 그리고 1.5초 안에 4회 이상 왕복했을 때만 전환이 확정되도록
  기준을 잡았습니다.
- **카메라 화면비를 9:16으로 크롭**: 실제 키오스크 화면 비율에 맞춰,
  헤드트래커 모드에서는 캡처된 가로 프레임을 좌우로 잘라 세로 9:16으로
  맞췄습니다(카메라 자체를 돌리지는 않았습니다). 손 제스처 모드는 기존
  16:9를 그대로 유지합니다.

### 8/3 — Windows·델파이7 키오스크 브랜치 재통합

다른 팀원이 개발해 온, 회사 키오스크 프로그램(델파이7)과 실제로 연동되는
Windows 브랜치에 헤드트래커(커서·select/home/calibration)를
재통합했습니다. 이 브랜치는 그동안 따로 진행돼 온 터라, 위 절들과 세부
구현(코끝 커서·머리 흔들기 전환 등)이 다를 수 있다는 점을 참고해 주세요.

- 얼굴 인식은 설정값 하나로 켜고 끌 수 있게 만들었고, **기본값은
  꺼짐**으로 설정했습니다
- 재통합 과정에서 크래시 버그 2건을 발견해 수정했습니다(한글 경로에서
  모델을 못 불러오는 오류, 디버그 화면이 죽는 문제)
- 델파이 연동용 실행 파일(run.exe)도 만들었습니다 — 기존 배치파일이 이
  PC에서 한글 인코딩 오류를 일으켜서 실행 파일로 바꿨습니다

## 5. 현재 헤드트래커 구성

| 기능 | 판정 기준 |
|---|---|
| 포인터 이동 | 코끝 위치 추적 |
| 선택/확인 | 입 벌리기 즉시, 또는 1.5초 응시 |
| 처음으로/뒤로가기 | 양 눈 감고 0.6초 유지 |
| 커서 재정렬 | 응시(dwell) — 일정 반경에 일정 시간 머무르면 확정 (구 입 오므리기, 7/30 오탐으로 교체) |
| 모드 전환(손↔머리) | 머리 좌우 흔들기 — 1.5초 안에 4회 이상 왕복해야 확정 (7/30 병합) |

시선(아이트래킹) 모드는 폐기됐습니다(위 7/22~7/23 항목 참고). 라이선스는
MediaPipe FaceLandmarker(Apache-2.0)이며, GPU는 필요 없습니다. 헤드트래커
모드에서는 카메라 화면비를 키오스크 화면에 맞춰 9:16으로 크롭해
사용합니다.
