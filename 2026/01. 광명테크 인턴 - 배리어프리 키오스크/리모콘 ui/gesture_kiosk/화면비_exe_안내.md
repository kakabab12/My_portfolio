# 화면비 — 16:9 데스크탑과 9:16 키오스크

같은 엔진으로 둘 다 씁니다. `--aspect`로 고르면 됩니다.

```
py -3 forehead.py --aspect desktop   # 16:9 가로 모니터
py -3 forehead.py --aspect kiosk     # 9:16 세로 키오스크
py -3 forehead.py                    # auto — 화면 해상도를 보고 결정
```

`head.py` · `eyebrow.py` · `forehead.py` 셋 다 같습니다. 안 주면 `auto`이고,
세로가 더 긴 화면이면 키오스크, 아니면 데스크탑으로 잡습니다. 한 대에서
화면비가 안 바뀐다면 그냥 실행해도 됩니다.

## 실행 파일로 만들려면

```
make_aspect_exes.bat
```

기준점 3가지 × 화면비 2가지 = 여섯 개를 임시 venv **하나에서** 한 번에
만듭니다. PyInstaller는 그 임시 venv에만 설치했다가 지웁니다 — 시스템
파이썬은 안 건드립니다.

| 기준점 | 16:9 가로 | 9:16 세로 키오스크 |
|---|---|---|
| 코끝 | `head_16-9_데스크탑.exe` | `head_9-16_키오스크.exe` |
| 눈썹 | `eyebrow_16-9_데스크탑.exe` | `eyebrow_9-16_키오스크.exe` |
| 이마 | `forehead_16-9_데스크탑.exe` | `forehead_9-16_키오스크.exe` |

**exe는 저장소에 안 올립니다.** `run.exe`·`head.exe` 등 다른 exe와 같은
방침입니다(`.gitignore` 참고) — 각 8MB라 여섯이면 46MB가 저장소에 박히고,
코드를 고칠 때마다 다시 빌드해 함께 올려야 해서 실제로는 낡은 exe가 남습니다.
필요할 때 위 명령으로 만드십시오.

exe는 얇은 실행기입니다. 안에서 `py -3.11 forehead.py --aspect desktop`을
부르므로 **엔진 파일과 같은 폴더에 두어야 합니다.** 붙는 `--aspect`는
기본값일 뿐이라, 뒤에 직접 주면 그쪽이 이깁니다.

## 화면비가 실제로 바꾸는 것 — 카메라 크롭 하나

엔진 파일은 셋뿐입니다. 화면비에 따라 달라지는 것이 **카메라 프레임 크롭
하나뿐**이라 여섯 벌로 나눌 이유가 없었습니다.

- 커서를 그리는 캔버스는 `GetSystemMetrics`로 측정한 실제 화면 해상도를 씁니다.
- 화면 끝을 보는 고개 각도은 EDID로 읽은 화면 실치수(mm)로 계산합니다.
- 랜드마크 척도는 두 눈 사이 거리로 정규화합니다.

셋 다 이미 모니터나 얼굴을 직접 보고 정하므로 화면비 때문에 손댈 것이 없습니다.

### 크롭이 뭘 하나

세로 크롭은 가로 프레임(1280×720)의 중앙만 남겨 9:16(405×720)을 만듭니다.
카메라를 물리적으로 돌리지 않고 세로 화면비를 맞추려고 넣은 것입니다.

가로 모니터에서 켜 두면 좌우 화각을 버리는 셈이라, 몸이 옆으로 움직이면
얼굴이 프레임 밖으로 나갑니다. 그래서 데스크탑 쪽은 끕니다.

끄더라도 **인식 정확도는 안 떨어집니다.** 높이를 안 건드리므로 얼굴이
차지하는 픽셀 크기가 그대로이고, 추적은 두 눈 사이 거리로 정규화해서 측정하기
때문입니다. 대신 추론 프레임이 405×720에서 1280×720으로 커져 그만큼
무거워집니다 — 키오스크 쪽에서 크롭을 유지하는 이유이기도 합니다.

### 세로로 돌려 단 화면

EDID는 **패널이 원래 생긴 모양**을 말합니다. 가로형 패널을 세로로 돌려
달아도 "597 × 336 mm"라고 답하는데, 사용자 앞의 화면은 336 × 597입니다.
그대로 쓰면 화면 끝을 보는 고개 각도의 가로·세로가 통째로 뒤바뀝니다(700mm 거리에서
23.1도 ↔ 13.5도).

윈도우 회전 설정을 묻지 않고 **픽셀 해상도와 대조**해 바로잡습니다. 실제
화면과 픽셀의 방향은 반드시 같으므로, 화면 설정과 드라이버 중 어느 쪽이
회전을 반영하든 성립합니다(`src/utils/display_size.py`).
