# 발견사항 — 데이터를 뽑다가 드러난 것

논문 초안을 쓰려고 수치를 모으는 과정에서 두 가지가 드러났습니다. 둘 다
초안을 그대로 내면 **틀린 논문**이 되는 사안이라 먼저 적어 둡니다.

---

## 1. 혼합비 r은 감도와 수학적으로 중복이다

### 무엇을 발견했나

혼합비 r을 0.05부터 1.0까지 훑었더니 회전이득·곡률·떨림·끌림 **네 지표가
전부 r에 정확히 비례**했습니다. r로 나눈 값이 소수점 여섯 자리까지 일정합니다
(`02_시뮬레이션_요약.md` §1).

수식이 그렇게 되어 있습니다.

```
p_r = 눈중점 + r x (코끝 − 눈중점)
u   = (p_r − 눈중점) / 안구간거리
    = r x (코끝 − 눈중점) / 안구간거리
```

r이 통째로 앞에 붙는 **순수 배율**입니다. 신호도 인공물도 잡음도 전부 같은
비율로 커지고 작아집니다. 따라서 r을 k배 하고 감도를 1/k배 하면 커서는
**완전히 동일**합니다. r 하나만 놓고 보면 아무것도 맞바꿀 수 없습니다.

### 그런데 왜 실기에서는 효과가 있었나

2026-08-27에 r을 0.5 → 0.3으로 낮추고 가로 감도를 1.124 → 2.0으로 올렸더니
세 증상이 해소되었다는 보고가 있습니다. 위 결론과 모순처럼 보이지만
**축별로 나눠 보면 설명됩니다.**

r은 가로·세로에 공통으로 걸리고, 감도는 축별로 따로 있습니다. 화면에 나타나는
유효 이득은 각각 `r × 감도X`와 `r × 감도Y`입니다.

| | r | 감도X | 감도Y | 가로 유효이득 (r·sx) | 세로 유효이득 (r·sy) |
|---|---|---|---|---|---|
| 이전 | 0.5 | 1.124 | 1.80 | 0.5620 | 0.9000 |
| 이후 | 0.3 | 2.000 | 1.80 | 0.6000 | **0.5400** |
| 변화 | | | | ×1.068 | **×0.600** |

가로는 거의 그대로(1.07배)인데 **세로만 0.6배로 줄었습니다.** 그 조정은
수학적으로 **"세로 감도를 40% 낮춘 것"** 과 같습니다.

그런데 당시 문제였던 두 증상 — 좌우로 움직일 때의 ∩ 곡률과 입 벌릴 때의
커서 밀림 — 은 **둘 다 세로로 나타나는 인공물**입니다. 그러니 세로 이득을
40% 줄인 것이 곧 해결이었습니다.

### 논문에서 어떻게 써야 하나

초안은 r을 "회전 감도와 세 부작용을 맞바꾸는 절충 손잡이"로 설명했습니다.
**그건 틀렸습니다.** 정확한 서술은 이렇습니다.

> 혼합비는 두 축에 공통으로 걸리는 배율이고 감도는 축별로 걸린다. 따라서
> 자유도는 r·sx 와 r·sy 두 개뿐이며 r 자체는 잉여 매개변수다. 실기에서
> 관찰된 개선은 "가로 이득을 유지한 채 세로 이득을 40% 낮춘" 효과이고,
> 이는 감도만으로도 같게 만들 수 있다.

**이 편이 오히려 더 좋은 결과입니다.** "손잡이를 잘 돌렸다"보다 "매개변수가
중복이었음을 밝히고 무엇이 실제로 작동했는지 분해했다"가 논문다운 기여입니다.
그리고 이건 실제로 측정으로 확인한 내용입니다.

## 2. 혼합 기준점은 이미 대체되었다

### 무엇을 발견했나

`forehead.py`는 현재 `ORIENTATION_MAPPING = True`입니다. 이 설정에서
`head_tracker.py`의 커서 계산은 다음 순서로 갑니다.

```python
def update(self, cursor_px, ...):
    if self._orientation_mapping and face is not None:
        result = self._update_from_orientation(face, now_sec)
        if result is not None:
            return result          # <- 여기서 끝난다
    ...                            # 혼합 기준점 경로는 여기 아래
```

즉 3차원 랜드마크가 정상적으로 오는 한 **혼합 기준점은 커서 위치를 결정하지
않습니다.** 지금 커서는 강체 랜드마크 22점의 Kabsch 정합으로 구한 **중립 자세
대비 상대 회전**으로 정해집니다(2026-08-31 도입).

`FOREHEAD_NOSE_BLEND_RATIO`가 지금 하는 일은 두 가지뿐입니다.

1. 3차원 랜드마크가 안 올 때의 **대체 경로**
2. `cam on` 미리보기의 **노란 점 표시**

### 왜 중요한가

초안은 혼합 기준점을 현재 설계로 설명했습니다. 그대로 내면 **이미 대체된 방식을
현재형으로 쓴 논문**이 됩니다. 심사에서 코드를 확인하면 바로 드러납니다.

### 어떻게 고칠 것인가

두 가지 길이 있습니다.

**(A) 설계 변천사로 다시 쓴다 — 권장**

> 제목(안): 몸 평행이동에 강인한 헤드 포인팅 — 기준점 축퇴에서 상대 회전까지

같은 문제(몸이 움직이면 커서가 밀린다)를 **세 번 고친 기록**으로 씁니다.

1. **미간 기준** — 얼굴 기준 좌표계를 켜고 싶었으나 기준점이 원점과 축퇴되어
   신호가 항상 0. 좌표계를 못 켬
2. **혼합 기준점** — 검증된 두 점의 선형 혼합으로 축퇴를 풀어 좌표계를 켬.
   다만 r이 감도와 중복이었고(§1), 코 성분을 섞은 대가로 곡률·입벌림·저조도
   문제가 따라옴
3. **상대 회전** — 기준점이라는 개념 자체를 버리고 강체 22점의 회전으로 감.
   2차원 투영을 거치지 않으므로 원근 곡률이 원리적으로 사라짐

각 단계에서 **무엇을 측정해 다음으로 넘어갔는지**가 논문의 뼈대가 됩니다.
이건 정직하고, 자료도 전부 있고, 그 자체로 방법론적 교훈이 있습니다.

**(B) 현재 설계만 쓴다**

상대 회전 + 화면 기하 기반 반폭(2026-09-05 작업)만 다룹니다. 깔끔하지만
혼합 기준점 이야기가 통째로 빠지고, 선행연구와의 차별점을 만들기가 더
어렵습니다.

## 3. 논문에 쓸 수 없는 것 — 정직하게

| 항목 | 왜 못 쓰나 |
|---|---|
| "사용자 평가" | 참가자를 모집한 실험이 없습니다. 개발자 본인과 팀장의 사용 보고뿐입니다 |
| 입 벌림 커서 밀림 수치 | 가상 카메라에 코 변형 모형이 없어 시뮬레이션으로는 0이 나옵니다 |
| 저조도 인식률 | 조명 모형이 없습니다. §1의 경로장 비만 실측입니다 |
| ISO 9241-411 처리량 | 측정하지 않았습니다 |
| 좌우 반전의 근본 원인 | 아직 모릅니다. 스위치로 덮어 둔 상태입니다 |

마지막 항목은 특히 조심해야 합니다. 2026-09-05에 실기에서 좌우가 반대로
도는 문제가 나왔고, **시뮬레이션은 그 경우를 "정상"으로 통과시켰습니다.**
가상 카메라의 거울 모형이 실제 장치와 어긋나 있다는 뜻이고, 그렇다면 이
폴더의 시뮬레이션 값 전반에 대해 "부호"에 관한 한 신뢰도를 낮춰 잡아야
합니다. 크기(떨림·끌림·오차)에는 영향이 없지만, 논문에서 방향성 주장을 할
때는 실기로 다시 확인해야 합니다.
