# 노트북에서 실행하기 (노트북 Claude 용)

이 글은 노트북에서 도는 Claude 가 읽고 그대로 따라 하도록 쓴 것이다. 사용자는 노트북 Claude 에 이 글 링크를 주고 "이대로 해 줘" 라고 하면 된다. 그림이 있는 자세한 설명은 [사용설명서](사용설명서.md)에 있다.

하는 일: 노트북 웹캠으로 사람 손을 재서, 연구실 PC 에 붙은 PiPER 팔이 손을 따라 움직이게 한다. 노트북은 손만 재고, 팔은 연구실 PC 가 움직인다.

| 누가 | 무엇을 |
|---|---|
| 노트북 Claude | 코드 받기, 설치, 점검(`check_setup.py`), 프로그램 켜기, 결과 정리 |
| 사용자 | A4 종이 놓기, 화면에서 종이 모서리 네 번 누르기, 손 올려놓기, 키 누르기 |
| 연구실 PC | 팔 쪽 프로그램(`robot_server.py`). 연구실 Claude 나 연구실 사람이 켠다 |

1~4절은 노트북 혼자 하는 것이라 팔이 움직이지 않는다. 연구실 PC 와 잇는 5절은 사용자가 하자고 할 때만 한다.

**11/20 바뀐 것 (사용자에게 알려 줄 것)**
- B: 연구실 PC 와 이어져 있을 때 팔을 저장해 둔 처음 자세로 돌려보낸다. 가는 중 SPACE 로 멈춘다.
- Z: 엄지와 손가락 끝을 종이에 대고 누르면 그 높이를 책상 높이로 잡는다 (11/19).
- 손떨림과 한 장면만 튀는 값은 기본으로 거른다. 끄려면 `--no-steady`.
- 연구실 PC 쪽은 바탕화면 'PiPER 조종' 아이콘으로 켤 수 있다. 처음 자세가 저장돼 있으면 종이 + 가 처음 자세의 집게 끝이다.

## 0. Claude 가 지킬 것

1. 사용자에게는 쉬운 한국어로 말하고, 한 번에 한 가지씩 시킨다.
2. 프로그램 창의 키(SPACE, R 등)는 사용자가 누른다. Claude 가 대신 누르지 않는다. SPACE(따라가기)는 실물 팔을 움직일 수 있는 키다.
3. 노트북에서 `--robot agxbus` 나 `--robot sdk` 로 켜지 않는다. 노트북에는 팔이 붙어 있지 않다.
4. 연구실 PC 주소는 사용자에게 묻는다. 그 주소를 파일에 적거나 GitHub 에 올리지 않는다. 이 저장소는 공개다.
5. 코드는 고치지 않는다. 이 노트북에서만 생기는 문제 때문에 꼭 고쳐야 하면, 무엇을 왜 바꿨는지 7절 결과에 같이 적는다. git push 는 하지 않는다. 고친 파일이 있으면 자동 업데이트가 그 파일과 부딪혀 새 코드를 받지 못할 수 있다. 그때는 `[업데이트] 못 받음` 이 나오니 사용자에게 알린다.
6. 웹캠 사진(`cam_check.jpg`)을 열어 보기 전에 "책상 사진을 한 장 찍어서 종이가 잘 보이는지 볼게요" 라고 사용자에게 먼저 말한다.

## 1. 코드 받기

이 폴더만 받는다(4 MB 쯤). 저장소 전체는 1 GB 가 넘으니 통째로 받지 않는다. 폴더 이름에 한글이 있어서 `11_*` 로 쓴다 (실제 이름은 `11_실물_PiPER/webcam_piper`).

```bash
git clone --depth 1 --filter=blob:none --sparse https://github.com/kakabab12/LAB-1309.git
cd LAB-1309
git sparse-checkout set --no-cone '11_*/webcam_piper/'
cd 11_*/webcam_piper
```

전에 받아 둔 적이 있으면 `LAB-1309` 폴더에서 `git pull` 만 한다. 보정 파일(`calib.json`)과 가상환경(`.venv`)은 git 이 건드리지 않는다.

한 번 받아 두면 그다음부터는 다시 받을 필요가 없다. `teleop.py` 와 `check_setup.py` 는 켤 때마다 GitHub 에서 새 코드를 스스로 받고, 받은 것이 있으면 같은 명령으로 저절로 다시 켠다 (`autoupdate.py`, 11/17). 인터넷이 안 되면 건너뛰고 지금 코드로 켠다. 11/17 오후보다 먼저 받은 폴더에는 이 기능이 없으니 `git pull` 을 한 번만 한다.

git 이 없으면 아래를 `get_webcam_piper.py` 로 저장해 `python3 get_webcam_piper.py` (윈도우는 `py get_webcam_piper.py`) 로 돌린다. 지금 폴더 아래에 `webcam_piper` 가 생긴다.

```python
import json, os, urllib.parse, urllib.request
REPO, PRE = "kakabab12/LAB-1309", "11_실물_PiPER/webcam_piper/"
d = json.load(urllib.request.urlopen(f"https://api.github.com/repos/{REPO}/git/trees/main?recursive=1"))
for t in d["tree"]:
    if t["type"] == "blob" and t["path"].startswith(PRE):
        dst = os.path.join("webcam_piper", *t["path"][len(PRE):].split("/"))
        os.makedirs(os.path.dirname(dst), exist_ok=True)
        urllib.request.urlretrieve(f"https://raw.githubusercontent.com/{REPO}/main/" + urllib.parse.quote(t["path"]), dst)
        print(dst)
```

## 2. 설치

Python 3.10~3.12 가 가장 안전하다. 인텔 맥은 MediaPipe 새 판이 없어서 반드시 3.12 이하여야 한다. 11/16 에 두 가지로 시험해서 둘 다 됐다: Python 3.12 + MediaPipe 1.2.3 + OpenCV 5.0, Python 3.12 + MediaPipe 0.10.21 + OpenCV 4.11.

가상환경은 이 폴더 안 `.venv` 에 만든다. 켜지(activate) 않고 가상환경의 python 을 바로 부른다. 아래부터 `PY` 는 이것이다.

| 컴퓨터 | `PY` |
|---|---|
| 맥, 리눅스 | `.venv/bin/python` |
| 윈도우 (Git Bash) | `.venv/Scripts/python.exe` |
| 윈도우 (PowerShell) | `.venv\Scripts\python.exe` |

맥, 리눅스:
```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python download_models.py
```

윈도우 (`py -3.12` 가 없으면 `py -0` 으로 깔린 판을 보고 3.10~3.12 중 하나를 쓴다):
```bash
py -3.12 -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe download_models.py
```

맞는 Python 이 없거나 `venv` 가 안 만들어지면, 사용자에게 물어본 뒤 uv 로 만든다. uv 는 Python 3.12 를 알아서 받아 온다.
```bash
uv venv --python 3.12 .venv
uv pip install --python .venv -r requirements.txt
```

`download_models.py` 는 MediaPipe 손 모델(약 7.8 MB)을 `models/` 에 받는다. 처음 한 번만 하면 된다.

## 3. 점검

```bash
PY check_setup.py
```

프로그램, 손 모델, 계산 시험(`test_geometry.py`, 10초쯤), 웹캠을 차례로 본다. 마지막 줄이 `점검: 모두 됨` 이면 된 것이다. `안 됨` 줄이 있으면 그 아래 `→` 뒤에 적힌 대로 한다.

맥은 웹캠을 처음 열 때 카메라 권한 창이 뜬다. 사용자에게 "허용" 을 누르라고 한다. 창에는 터미널이나 Claude 앱 이름이 나올 수 있다. 거부했다면 시스템 설정 > 개인정보 보호 및 보안 > 카메라에서 켜고 다시 돌린다.

이제 사용자에게 책상을 놓게 한다.
- 노트북을 책상에 두고 화면을 사람 쪽으로 세운 다음, 아주 살짝 앞으로 숙인다.
- A4 를 가로로, 노트북에서 사람 쪽으로 60~70 cm 앞에 놓는다.
- 종이 한가운데에 연필로 + 를 그린다. 가로로 놓았을 때 왼쪽 끝에서 148 mm, 사람 쪽 끝에서 105 mm 인 곳이다.
- 사람 뒤에 창문이 있으면(역광) 손을 잘 못 찾는다.

다 놓았으면 `PY check_setup.py` 를 한 번 더 돌리고, 사용자에게 말한 뒤 `cam_check.jpg` 를 본다. 볼 것은 세 가지다.
- A4 네 모서리가 다 보이는가
- 종이 위로 손을 20 cm 쯤 들어도 화면 안에 있을 만큼 위쪽에 여유가 있는가
- 너무 어둡거나 역광이 아닌가

안 맞으면 노트북 화면 각도나 종이 자리를 바꾸게 한다.

## 4. 노트북 혼자 해 보기 (팔 없음)

```bash
PY teleop.py
```

이 명령은 사용자가 끌 때까지 끝나지 않으므로 뒤에서 돌린다. 창이 안 보이면 다른 창 뒤에 있을 수 있다. 그래도 안 뜨면 사용자에게 자기 터미널에서 이 폴더로 가서 같은 명령을 치게 한다.

창 왼쪽은 웹캠 화면(거울처럼 좌우가 뒤집힘), 오른쪽은 가상 팔이다. 화면 글자는 영어다. 사용자에게 아래를 하나씩 시킨다.

1. 창을 한 번 눌러 앞으로 가져온다. 한/영 키로 영어 입력 상태인지 본다. 한글 상태면 S, P 같은 키가 안 먹을 수 있다.
2. 화면에서 종이 모서리 네 개를 마우스로 차례로 누른다. 화면에서는 사람 쪽 모서리가 위에, 노트북 쪽 모서리가 아래에 보이고 왼쪽·오른쪽은 보이는 그대로다. 그래서 순서는 화면의 위-왼쪽 → 위-오른쪽 → 아래-오른쪽 → 아래-왼쪽이다. 잘못 누르면 Backspace.
3. 파란 점들이 종이 위에 고르게 앉아 있으면 Enter, 어긋나 있으면 Backspace 로 다시 누른다.
4. 오른손을 종이 위에 쫙 펴서 올려놓는다. 손바닥 가운데를 + 에 두고 손가락은 노트북 쪽을 향하게 한다. 왼손은 화면 밖에 둔다. 그대로 S 를 누르고 1초 남짓 움직이지 않는다.
5. 화면에 `saved. scale ...` 가 뜨면 보정이 끝난 것이다.
6. 위치 확인을 다섯 번 한다. 다섯 손가락 끝을 새 부리처럼 한데 모아 종이 + 에 대고 P 를 누른다. 그다음 종이 네 모서리에 하나씩 대고 P 를 누른다. 누를 때마다 화면에 `P: ... off by x .. y .. cm` 가 뜨고 `checks.jsonl` 에 남는다. 모서리나 + 에 대지 않은 채로 누른 것은 빼고 다시 하면 된다 (7절에서 그렇다고 적는다).
7. 해 보고 싶으면 SPACE 로 가상 팔 따라가기를 켜고 손을 움직여 본다. 노트북 혼자일 때는 화면 속 가상 팔만 움직인다. 다시 SPACE 로 멈춘다. TAB 을 누르면 손 전체 ↔ 엄지·검지로 쥐는 모양이 바뀐다 (따라가기는 멈추니 SPACE 로 다시).
8. Q 로 끈다.

끈 뒤 Claude 가 결과를 본다.
```bash
PY check_setup.py --report
```

| 줄 | 좋음 | 아니면 |
|---|---|---|
| 모서리 오차 | 3 px 이하 | 다시 켜서 C 를 누르고 모서리부터 다시 |
| 손바닥 가운데가 + 에서 | x, y 둘 다 1 cm 안 | 손바닥을 + 에 더 정확히 두고 S 로 다시 |
| MediaPipe 가 이 오른손을 부르는 이름 | 20/20 처럼 한 이름으로 몰림 (`Left`, `Right` 어느 쪽이든 괜찮다. 두 손이 보일 때 이 이름으로 고른다) | 16/20 보다 적으면 왼손을 화면 밖에 두고 S 로 다시 |
| 손 3D | `ok` 나 `MIRRORED` 둘 다 괜찮다 (프로그램이 맞춰 씀). 거울상 표가 0/20 이나 20/20 가까이면 확실하다 | 6/20~14/20 처럼 반반이면 판단이 불확실하니 S 로 다시 |
| P 위치 확인 | 바닥 위 차이 가운데값 1.5 cm 이하 | 3 cm 를 넘으면 C 로 다시. 그래도 크면 노트북을 높은 곳(책 몇 권 위)에 올리고 다시 |
| P 높이 | 손가락 끝을 종이에 댔으므로 1 cm 안팎 | 몇 cm 씩 뜨면 보정을 다시 |

보정은 `calib.json` 에 남아서 다음에 켜면 바로 불러온다. 노트북이나 종이를 옮겼으면 C 로 처음부터 다시 한다.

## 5. 연구실 PC 와 잇기 (사용자가 하자고 할 때만)

1. 연구실 PC 에서 `robot_server.py` 가 켜져 있어야 한다. 사용자가 연구실 Claude 에 "robot_server 가상 팔로 켜 줘" 라고 하거나 연구실 사람이 켠다. 켜지면 연구실 PC 창에 `이 PC 주소: ...` 가 나온다.
2. 사용자에게 그 주소를 묻는다.
3. `teleop.py` 가 꺼진 상태에서 주고받기만 시험한다. 따라가기를 켜지 않으므로 팔은 움직이지 않는다.
   ```bash
   PY check_setup.py --no-cam --robot-pc 연구실PC주소
   ```
   `답장 옴` 이 나오면 된다. 답장이 없으면 `ping 연구실PC주소` 를 해 본다. ping 도 안 되면 두 컴퓨터가 서로 다른 망이다. 같은 공유기에 붙이거나, 사용자가 원하면 둘 다 Tailscale 같은 사설망 프로그램에 같은 계정으로 넣고 그 주소(100. 으로 시작)를 쓴다 (사용설명서 6-3).
4. 손 측정을 보낸다.
   ```bash
   PY teleop.py --send 연구실PC주소
   ```
   화면 오른쪽 아래에 `preview arm`(가상 팔)과 `ping .. ms` 가 나오면 이어진 것이다. 보정은 4절에서 한 것을 그대로 쓴다. SPACE 를 누르면 연구실 PC 의 가상 팔이 손을 따라간다.
5. 11/18 에 손 위치 푸는 방식이 `oat` 로 바뀌었다. 그 전에 보정한 노트북은 켤 때 `저장된 보정은 --solver pnp 로 한 것` 이 나온다. 그러면 사용자에게 손을 종이에 펴서 올려놓고 S 를 누르게 한다 (손 보정만 다시, 모서리는 그대로). 노트북이나 종이를 옮겼으면 C 로 모서리부터 다시.
6. 위아래 확인: 따라가기를 켜기 전에, 다섯 손가락을 모은 손을 + 위에서 10 cm 쯤 천천히 들었다 내리게 하고 화면 위 `hand ... z` 숫자가 같이 오르내리는지 본다. 그다음 SPACE. 이때 R 로 10~20초 기록해 두면 연구실 PC 에서 `replay_raw.py` 로 방식별 높이를 비교할 수 있다.

실물 팔: 연구실 쪽이 `--robot agxbus` 로 켜면 노트북 화면에 빨간 `REAL ARM` 이 뜬다. 노트북 명령은 같다. 이때 Claude 는 "팔 옆에 사람이 있고 팔 둘레가 비어 있다" 는 말을 사용자에게 듣기 전에는 SPACE 를 누르라고 하지 않는다. 처음 몇 번은 손을 천천히 움직이게 하고, 이상하면 바로 SPACE 로 멈추게 한다 (손을 1초 넘게 놓쳐도 멈춘다).

## 6. 문제가 생기면

| 보이는 것 | 할 것 |
|---|---|
| `웹캠 0 을 못 엶` | 줌·카메라 앱 같은 다른 프로그램을 끈다. 맥은 카메라 권한. 외장 카메라면 `--cam 1` |
| 창은 뜨는데 키가 안 먹음 | 창을 한 번 누른다. 한/영 키로 영어 |
| `hand not found` | 더 밝게, 손 전체가 화면 안에, 역광 피하기 |
| pip 가 mediapipe 를 못 찾음 | Python 판이 맞지 않는다. 3.12 가상환경으로 (2절 uv) |
| 창이 화면보다 큼 | 웹캠이 1280x720 이면 창은 가로 1360, 세로 540 화소다. 윈도우 디스플레이 배율을 낮춘다 |
| `no answer from` (빨간 글씨) | 5절 3번 |
| 그 밖 | 사용설명서 11절. 그래도 모르겠으면 오류 전체를 7절 결과에 붙인다 |

## 7. 결과 알려 주기

끝나면 아래를 한 덩어리로 사용자에게 보여 주고, 연구실 Claude 에 그대로 붙여 넣으라고 한다. 이름이나 주소 같은 개인 정보는 들어 있지 않다.

1. `PY check_setup.py --report` 출력 전체
2. `PY check_setup.py` 의 `안 됨` 줄 (있었다면)
3. 모서리나 + 에 대지 않고 누른 P 가 있었다면 몇 번째였는지
4. 해 본 것 (노트북 혼자 / 가상 팔과 연결 / 실물 팔)과, 사용자가 느낀 것 (예: 가상 팔이 늦게 따라옴, 손을 자주 놓침)
5. 생긴 문제와 바꾼 것 (코드를 고쳤다면 무엇을 왜)
