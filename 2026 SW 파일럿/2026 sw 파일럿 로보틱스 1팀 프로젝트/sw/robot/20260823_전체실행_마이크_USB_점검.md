# 2026-08-23 TurtleBot3 전체실행·마이크·USB 점검 기록

## 요청과 전제

- 사용자는 Jetson/TurtleBot3 재부팅 뒤 `TurtleBot3 전체 실행`에서 오류·버그가 나는지 점검을 요청했다.
- 대화 시작 전 이미 여러 차례(4회 이상) 재부팅한 상태였다.
- 안전을 위해 자동 A→B→C→D→A 순찰 미션은 실행하지 않고, 동일한 기동 구성에서 waypoint 미션만 제외한 진단 기동을 했다.
- 점검 중 기존 실행 프로세스는 정상 종료했다. 코드 변경은 하지 않았다.

## 사전 확인

다음 정적 검사는 모두 통과했다.

- 전체실행 및 보조 셸 스크립트 `bash -n`
- ROS 브리지/launch Python 파일 `py_compile`
- `python3 -m unittest tests.test_cmd_vel_mux`: 7개 통과
- ROS 2 Humble 및 필요한 패키지 확인:
  `turtlebot3_bringup`, `turtlebot3_navigation2`, `nav2_bringup`, `joy`,
  `teleop_twist_joy`, `sound_anomaly`

기동 직전 실제 USB 장치는 정상 인식되어 있었다.

| 역할 | 장치 |
| --- | --- |
| TurtleBot3 OpenCR | `/dev/ttyACM0` |
| LDS-03 LiDAR | `/dev/ttyUSB0` |
| Xbox 조이스틱 | `/dev/input/js0` |
| 카메라 | `/dev/video0` ~ `/dev/video3` |
| USB 마이크 | MUSIC-BOOST USB Microphone |

## 전체 구성 기동 결과

실제 실행한 명령은 순찰 없이 다음과 같았다.

```bash
bash scripts/run_navigation_gesture_joystick.sh --usb-port /dev/ttyACM0
```

다음 단계는 정상적으로 올라왔다.

1. TurtleBot3 bringup: OpenCR 포트 열기·보드레이트 변경·자이로 보정 완료
2. OpenCR `/battery_state` 수신 및 `/turtlebot3_node` 동작
3. LDS-03 LiDAR 노드와 `/scan` 수신
4. 소리 이상감지 노드 기동
5. 제스처 서버, 속도 mux, Wi-Fi 장갑 노드, 조이스틱 노드 기동
6. Nav2/AMCL/RViz 및 `/navigate_to_pose` 관련 구성 기동
7. 제스처 `cmd_vel` 브리지 기동

ROS graph에서는 `/turtlebot3_node`, `/lidar_node`, `/sound_anomaly_node`,
`/gesture_cmd_vel_bridge`, `/gesture_nav_cmd_vel_mux`, `/wifi_glove_teleop`,
`/joy_node`, `/amcl`, `/controller_server`, `/planner_server`, `/bt_navigator` 등
필요 노드가 확인되었다.

## 관측된 경고와 USB 장애

### 소리 이상감지 경고

소리 이상감지 노드는 기동됐지만 다음 경고가 반복됐다.

- 오디오 입력 `input overflow`
- `Audio queue full; dropping an input block`
- 저장 모델의 scikit-learn 1.9.0과 현재 런타임 1.7.2 불일치 경고

이는 소리 판정의 지연·누락 가능성을 뜻하며, 모델/런타임 버전 정렬과 오디오 처리
부하 점검이 필요하다.

### USB 컨트롤러 장애

커널 로그의 주요 순서는 다음과 같다.

| 시각 | 관측 |
| --- | --- |
| 14:40경 | 카메라 USB reset이 반복됨 (소리 감지 기동 전) |
| 14:43:28경 | 소리 이상감지 노드 시작 |
| 14:43:47 | `tegra-xusb ... xHCI host controller not responding` |
| 14:43:47 | `HC died; cleaning up` 후 USB 허브 전체 disconnect |

같은 USB 허브에 연결된 OpenCR·LiDAR·카메라·조이스틱·마이크가 동시에 사라졌다.
따라서 소리 감지 코드가 직접 재부팅한 것은 아니다. 해당 노드는 ALSA 마이크 입력과
ROS LED 토픽만 사용하며 시스템 재부팅/USB 리셋 호출은 없다. 다만 마이크 입력과
여러 카메라의 동시 사용이 USB 대역폭·전원·허브 불안정을 촉발했을 가능성은 남아 있다.

OpenCR이 실행 중 재부팅되면 기존 `turtlebot3_node`는 끊긴 직렬 연결을 자동 복구하지
못하고 송수신 오류를 반복한다. 이 경우 전체실행을 종료한 뒤 OpenCR이 다시 인식된 후
새로 시작해야 한다.

## 현재 상태와 다음 조치

- 점검 중 시작한 전체실행 프로세스는 정상 종료했다.
- USB 컨트롤러가 죽은 뒤에는 OpenCR만 재부팅해도 복구되지 않았다.
- USB 마이크는 분리했다.
- 현재는 Jetson을 완전히 재부팅해야 USB 컨트롤러 및 OpenCR·LiDAR·카메라·조이스틱이
  다시 인식된다.

재부팅 뒤에는 마이크를 계속 분리한 상태에서, 소리 이상감지 단계만 제외한 전체 기동으로
재시험해 마이크/소리 처리의 연관성을 분리 확인한다.
