# 설치·실행 순서

자세한 설명은 [README.md](README.md) 참고. 이 파일은 순서만 빠르게 보기 위한 체크리스트다.
**손 인식·판정·ROS2까지 전부 젯슨에서 처리**하고, 노트북은 카메라 영상만
네트워크로 내보낸다 ([README.md](README.md)의 "노트북 카메라 + 젯슨
중앙집중" 참고, 이 구성이 검증된 권장 구성이다).

이 문서는 두 파트다 — **[설치]는 딱 한 번만**, **[매번 실행]은 작업실 갈
때마다 반복**한다.

---

# [설치] — 한 번만 하면 됨

## 노트북 — 카메라 송출 준비

1. 라이브러리 설치 (mediapipe 불필요 — 순수 영상 송출만)
   ```bash
   pip install -r requirements-camera-server.txt
   ```

## 핫스팟으로 노트북 · 젯슨 연결

2. 휴대폰 개인 핫스팟 켜기 (또는 윈도우 **설정 → 네트워크 및 인터넷 → 모바일 핫스팟**)
3. 노트북을 그 와이파이에 연결
4. **젯슨을 그 와이파이에 연결** — 방법은 둘 중 하나:
   - 젯슨에 모니터·키보드가 물려있으면: 화면 우측 상단 와이파이 아이콘
     클릭 → 핫스팟 SSID 선택 → 암호 입력 (일반 우분투 데스크톱과 동일)
   - 모니터 없이 터미널(SSH 등)로만 접근 가능하면:
     ```bash
     nmcli device wifi list                          # 주변 와이파이 목록 확인
     nmcli device wifi connect "<SSID>" password "<암호>"
     ```
   ★ 젯슨이 지금 유선(랜선)이나 다른 와이파이로 이미 접속돼 있어서 처음
   SSH로 들어간 거라면, 위 명령 실행 후 IP가 바뀌므로 기존 SSH 세션은
   끊길 수 있다 — 당황하지 말고 새 IP(아래 6번)로 다시 접속할 것.
5. 노트북의 IP 주소 확인
   ```powershell
   ipconfig
   ```
   (핫스팟 어댑터의 IPv4 주소를 적어둔다 — 아래에서 `<노트북IP>` 자리에 씀)
6. 윈도우 방화벽이 새 네트워크를 "공용"으로 잡으면 인바운드가 막힐 수 있다 —
   해당 네트워크를 "개인 네트워크"로 바꾸거나, 방화벽 허용 알림이 뜨면 허용

★ **휴대폰 핫스팟을 쓰면 IP가 매번 세션마다 바뀔 수 있다** — 지난번에
적어둔 IP를 그대로 믿지 말고, 갈 때마다 5번(`ipconfig`)으로 새로 확인할
것. (윈도우 모바일 핫스팟은 보통 `192.168.137.1`로 고정이라 이 문제가 적다.)

## 젯슨 오린 나노 — 제스처 엔진 준비

7. 파이썬 라이브러리 설치
   ```bash
   pip3 install -r requirements-gesture.txt
   ```
   (mediapipe/opencv-contrib-python이 aarch64 wheel 문제로 안 깔리면
   버전 안 박고 `pip3 install mediapipe opencv-contrib-python`로 재시도)
8. 손 인식 모델 다운로드 (약 8MB)
   ```bash
   python3 scripts/download_weights.py
   ```
9. `configs/config.yaml`의 `camera.devices`에 노트북 스트림 주소 입력
   ```yaml
   camera:
     devices: ["http://<노트북IP>:8090/cam/0/stream"]
   ```
   ★ 위 "IP가 매번 바뀔 수 있다"에 해당하면, 이 값도 갈 때마다 최신 IP로
   다시 고쳐야 한다는 뜻이다.

## 젯슨 오린 나노 — ROS2 + 터틀봇3 (이미 설치돼 있으면 10~14번은 스킵)

10. locale·apt 저장소 설정 후 ROS2 Humble 설치
    ```bash
    sudo apt update && sudo apt install -y locales
    sudo locale-gen en_US en_US.UTF-8
    sudo update-locale LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8
    sudo apt install -y software-properties-common
    sudo add-apt-repository universe
    sudo apt update && sudo apt install -y curl
    sudo curl -sSL https://raw.githubusercontent.com/ros/rosdistro/master/ros.key \
      | sudo gpg --dearmor -o /usr/share/keyrings/ros-archive-keyring.gpg
    echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/ros-archive-keyring.gpg] \
      http://packages.ros.org/ros2/ubuntu $(. /etc/os-release && echo $UBUNTU_CODENAME) main" \
      | sudo tee /etc/apt/sources.list.d/ros2.list > /dev/null
    sudo apt update && sudo apt upgrade -y
    sudo apt install -y ros-humble-ros-base python3-colcon-common-extensions python3-rosdep
    sudo rosdep init
    rosdep update
    echo "source /opt/ros/humble/setup.bash" >> ~/.bashrc
    source ~/.bashrc
    ```
11. 터틀봇3 ROS2 패키지 설치
    ```bash
    sudo apt install -y ros-humble-turtlebot3-msgs ros-humble-turtlebot3 \
      ros-humble-dynamixel-sdk ros-humble-hls-lfcd-lds-driver
    ```
    (안 되면 README.md의 "소스로 빌드" 절차 참고)
12. 로봇 모델 환경변수 설정 (버거)
    ```bash
    echo "export TURTLEBOT3_MODEL=burger" >> ~/.bashrc
    source ~/.bashrc
    ```
13. OpenCR 연결 확인 (로봇 전원이 켜져 있어야 보임 — 아래 [매번 실행] 0번 먼저)
    ```bash
    ls /dev/ttyACM*
    ```
14. 브리지용 파이썬 라이브러리 설치
    ```bash
    pip3 install -r requirements-ros2.txt
    ```

## 검증 (설치 다 끝난 뒤, 한 번 — 카메라·로봇 불필요)

15. 단위 테스트 — 로직만 검증, 어느 컴퓨터에서 돌려도 됨
    ```bash
    python -m unittest discover tests -v
    ```

# [매번 실행] — 작업실 갈 때마다 반복

**순서를 지킬 것 — 로봇에 실제로 손대는 부분(7번, 브리지)을 가장 나중에 켠다.**

0. **배터리 2개 다 켜기** — OpenCR/모터용 배터리와 젯슨용 배터리가 따로
   분리돼 있으므로 **둘 다** 켜야 한다. 젯슨 배터리만 켜고 OpenCR 쪽을
   빠뜨리면 2번(bringup)에서 OpenCR을 못 찾고, 반대로 OpenCR만 켜고
   젯슨이 꺼져 있으면 당연히 아무 명령도 못 내린다.
1. 노트북·젯슨을 핫스팟으로 연결 (위 설치 2~6번과 동일한 방법 — 매번 새로
   연결해야 하고, IP도 휴대폰 핫스팟이면 매번 새로 확인)
2. **젯슨**: 터틀봇3 bringup 실행
   ```bash
   ros2 launch turtlebot3_bringup robot.launch.py
   ```
3. **젯슨**: bringup 단독 확인 (또 다른 터미널) — 이 저장소 코드를 아직
   하나도 안 붙인 상태로 먼저 모터가 도는지 확인한다:
   ```bash
   ros2 topic list                              # /cmd_vel 보여야 함
   ros2 run turtlebot3_teleop teleop_keyboard    # w/a/s/d/x로 바퀴 확인, 끝나면 Ctrl+C
   ```
4. **노트북**: 카메라 송출 시작
   ```bash
   python camera_server/camera_server.py --devices 0 --port 8090
   ```
5. **젯슨**: 노트북 스트림 연결 확인 (IP가 바뀌었으면 `configs/config.yaml`도
   같이 갱신 — 위 설치 9번)
   ```bash
   curl http://<노트북IP>:8090/health
   ```
6. **젯슨**: 제스처 엔진 실행 (또 다른 터미널)
   ```bash
   python3 -m src.server.app
   ```
   브라우저로 `http://<젯슨IP>:5000/`을 열어 카메라 화면·`armed`가 뜨는지
   확인(선택이지만 처음엔 권장). 로봇은 아직 안 움직인다 — 다음 단계(브리지)
   전까지는 숫자만 계산할 뿐 `/cmd_vel`에 아무것도 안 보낸다.
7. **젯슨**: 브리지 실행 (또 다른 터미널) — 전부 젯슨 자신이므로 localhost.
   **이 명령을 실행하는 순간부터 로봇이 실제로 반응한다.**
   ```bash
   python3 ros2_bridge/cmd_vel_bridge.py --base-url http://127.0.0.1:5000
   ```
8. 노트북 카메라 앞에서 손짓 — 중앙에서 손바닥 펴고 약 1.2초 유지해 잠금
   해제(ARMED) 후 조작. **처음에는 바퀴가 지면에 안 닿게 로봇을 들거나
   열린 공간에서 먼저 테스트할 것.**

## 끝낼 때

- Ctrl+C로 7번(브리지) → 6번(엔진) → 4번(카메라 송출) → 2번(bringup)
  순서로 끄고, 로봇 전원을 끈다. 순서가 중요한 건 아니고, 이 순서면
  "로봇이 명령을 받는 경로"부터 먼저 끊겨 안전하다는 정도의 의미다.
