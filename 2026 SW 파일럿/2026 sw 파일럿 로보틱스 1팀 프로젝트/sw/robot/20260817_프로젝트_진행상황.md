# 터틀봇3 손 제스처·SLAM 통합 프로젝트 진행상황

기록일: 2026-08-17  
프로젝트 경로: `/home/user/sw/robot`

## 1. 최종 목표

TurtleBot3가 평소에는 SLAM/Nav2 기반으로 자율주행하고, 카메라에서 손 제스처 모드를 켜면 제스처가 수동 제어권을 가져가도록 구성한다. SLAM과 Nav2는 항상 실행하며 제스처 기능만 ON/OFF한다. Nav2와 제스처가 동시에 터틀봇 속도에 적용되지 않도록 단일 속도 mux를 사용한다.

## 2. 현재 제스처 정의

| 제스처 | 동작 |
|---|---|
| 엄지만 위로 👍 | 제스처 모드 ON |
| 엄지만 아래로 👎 | 제스처 모드 OFF, AUTO/Nav2 복귀 |
| 주먹 | 정지 |
| 검지 1개 | 전진 30cm |
| 검지·중지 2개 | 후진 30cm |
| 손가락 3개 | 우회전 90° |
| 엄지를 접고 나머지 4개 | 좌회전 90° |
| 다섯 손가락을 모두 편 손등 | RViz에서 마지막으로 찍은 2D 목표 좌표로 Nav2 이동 |
| 다섯 손가락을 모두 편 손바닥으로 좌우 3회 흔들기 | 180° 회전 |

### 제스처 실행 규칙

- 30cm·90° 명령은 1회 트리거 방식이다.
- 포즈가 한 번 확정되면 손을 내려도 `/odom`으로 목표 거리·각도를 측정하며 끝까지 이동한다.
- 같은 포즈를 계속 유지하면 중복 실행하지 않는다.
- 동작 중 다른 손가락 포즈가 확정되면 기존 동작을 즉시 중단하고 현재 위치에서 새 목표를 시작한다.
- 예: 3손가락 우회전 중 4손가락이 들어오면 우회전을 버리고 좌회전 90°를 즉시 새로 시작한다.
- 주먹 비상정지는 포즈 변경 순간의 오인을 막기 위해 원샷 실행 중 약 0.25초 유지 시 취소한다.
- `/odom`이 없거나 0.5초 이상 오래되면 상대 이동을 시작하지 않거나 취소한다.

## 3. 4손가락과 흔들기 충돌 해결

초기에는 엄지를 개수에서 제외했기 때문에 4손가락 좌회전과 다섯 손가락 흔들기가 같은 `four`로 처리됐다. 현재는 다음과 같이 분리했다.

- 엄지 접힘 + 검지·중지·약지·새끼 폄: `four`, 좌회전 90°
- 엄지 포함 다섯 손가락 모두 폄: `open`, 흔들기 후보
- 손을 화면에 넣는 최초 이동 하나는 흔들기로 세지 않는다.
- 반대 방향 이동이 확인된 후에만 흔들기 진행 상태로 들어간다.
- 직전 극점 기준 화면 너비 약 5% 이상 이동을 한 구간으로 센다.
- 빠르게 흔들며 손 검출이 한두 프레임 빠져도 3초 타임아웃 전에는 누적 횟수를 유지한다.
- 좌우 왕복 3회가 확인되면 `wave`를 발생시켜 180° 회전한다.

## 4. 손 인식 정확도 개선

### 적용한 튜닝

- 손 검출·존재·추적 신뢰도 문턱: 각각 `0.30`
- 최소 손 크기 비율: `0.035`
- 손가락 펴짐 비율: `1.03`
- 손가락 접힘 확인 비율: `0.97`
- 일반 포즈 확인: 2프레임
- 4손가락 확인: 2프레임
- 손등 확인: 6프레임
- 손가락 하나가 경계 상태여도 비율 1.0을 기준으로 가까운 펴짐/접힘 상태에 귀속

### 실물 카메라 확인 결과

- 손 자체는 약 `0.97~0.99` 신뢰도로 검출되는 것을 확인했다.
- MediaPipe `world_landmarks`가 실제로 편 손가락을 접힌 것으로 계산하는 구도가 발견됐다.
- 손가락 개수 판정은 사용자가 보는 화면 투영 랜드마크를 우선 사용하도록 변경했다.
- 변경 후 실시간 API에서 `shape: "four"`가 연속 출력되는 것을 확인했다.

## 5. 카메라 움직임에 따른 커서 이동 보정

터틀봇 또는 카메라가 움직일 때 배경 전체 이동이 손 커서에 섞이는 현상을 줄이기 위해 `src/postprocess/camera_motion.py`를 추가했다.

- 배경 특징점 광학 흐름 사용
- 평행 이동, 회전, 배율 변화를 affine 변환으로 추정
- 손 영역은 배경 추정에서 제외
- 배경 특징점이 부족하거나 프레임 간 변화가 비정상적으로 크면 보정값을 사용하지 않음
- 카메라 전환 시 필터와 기준 좌표를 초기화

## 6. SLAM/Nav2와 제스처 제어권 구조

현재 속도 경로는 다음과 같다.

```text
Nav2 /cmd_vel -----------┐
                        ├─ cmd_vel_mux ─ /cmd_vel_muxed ─ turtlebot3_node
Gesture /cmd_vel_gesture┘
```

- 제스처 모드 OFF: mux가 Nav2 `/cmd_vel`만 선택
- 제스처 모드 ON: mux가 `/cmd_vel_gesture`만 선택
- 제어권 전환 순간 정지 명령 1회 출력
- 선택된 입력이 0.5초 이상 끊기면 정지
- TurtleBot3 하드웨어 노드는 `/cmd_vel_muxed`만 구독
- Nav2와 제스처가 하드웨어에 동시에 직접 쓰지 않음

초기에는 Nav2 최종 `/cmd_vel`을 launch 전체 remap으로 바꾸려고 했으나 composable Nav2 내부 토픽까지 함께 remap되어 충돌했다. 이를 폐기하고 하드웨어 입력만 `/cmd_vel_muxed`로 격리하는 방식으로 변경했다.

## 7. 제스처 모드와 Nav2 동작

- 시작 기본값은 제스처 OFF이다.
- 엄지 위로 ON해도 Nav2와 SLAM 노드를 종료하거나 목표를 취소하지 않는다.
- 속도 출력권만 제스처로 전환한다.
- 엄지 아래로 OFF하면 진행 중 제스처 상대 이동을 취소하고 Nav2에 속도 출력권을 돌려준다.
- RViz 저장 좌표 이동은 Nav2가 담당하므로 목표가 접수되면 제스처 모드를 OFF로 바꾼다.
- Nav2 목표 실행 중 주먹을 보이면 목표를 취소하고 정지한다.

## 8. RViz 2D 목표 좌표

- 브리지가 RViz의 마지막 `/goal_pose`를 저장한다.
- 다섯 손가락을 편 손등 제스처가 확정되면 저장된 좌표를 `NavigateToPose` 액션으로 전달한다.
- 저장 좌표가 없거나 Nav2 액션 서버가 준비되지 않으면 명령을 거부하고 정지 상태를 유지한다.
- Nav2 실행 전 RViz의 `2D Pose Estimate`로 AMCL 초기 위치를 지정해야 한다.

## 12. 현재 알려진 확인사항

- 실물에서 3손가락 우회전 중 엄지를 접은 4손가락으로 바꿀 때 즉시 좌회전으로 전환되는지 최종 주행 확인이 필요하다.
- 다섯 손가락을 모두 편 손바닥 좌우 3회 흔들기가 실제 180°를 완주하는지 최종 주행 확인이 필요하다.
- 손등과 손바닥 분류는 사용자 손 방향과 카메라 거울 좌표의 영향을 받으므로 RViz 저장 좌표 이동을 양손 각각 확인하는 것이 좋다.
- `/dev/video2`를 사용할 계획이면 실제 장치 번호를 확인해 `configs/config.yaml`의 `camera.devices`를 수정해야 한다.
- RViz에서 AMCL 초기 위치를 찍지 않으면 `map → odom` 변환이 없어 Nav2가 정상 주행하지 않는다.

## 14. 안전 주의

- 최초 시험은 로봇 주변을 비우고 넓은 공간에서 진행한다.
- 긴급 정지는 주먹을 유지하거나 엄지 아래로 제스처 모드를 OFF한다.
- 30cm·90° 원샷 동작은 손을 내려도 계속되므로 손을 빼는 것만으로는 정지하지 않는다.
- Nav2와 제스처가 동시에 하드웨어에 적용되지 않도록 반드시 `robot_with_mux.launch.py`로 bringup한다.

## 15. 조이스틱 통합

- `/home/user/turtlebot3_ws/install/setup.bash`는 조이스틱 파일이 아니라 ROS 2 overlay 환경 설정 스크립트이다.
- `turtlebot3_joystick`, `joy`, `teleop_twist_joy` 패키지 설치를 확인했다.
- `/dev/input/js0` 장치가 `Xbox 360 Controller`로 정상 열리는 것을 확인했다.
- `ros2_bridge/joystick_with_mux.launch.py`를 추가했다.
- teleop 출력은 하드웨어로 직접 보내지 않고 `/cmd_vel_joy`를 통해 mux로 보낸다.
- mux 우선순위: 조이스틱 ON > 제스처 ON > AUTO/Nav2.
- OK 사인을 짧게 보여주면 `/joystick_mode`가 ON된다.
- ON에 사용한 OK 사인을 풀었다가 다시 2초간 유지하면 조이스틱이 OFF된다.
- 조이스틱 ON 시 진행 중 제스처 이동을 취소하고 제스처 모드를 OFF로 한다.
- 조이스틱 OFF 시 일반 제스처 모드가 자동으로 ON된다.
- 실물 테스트에서 전진·후진이 반대로 확인되어 직선 축 부호를 `-0.08`에서 `+0.08`로 수정했다.
- 왼쪽 스틱 상하 최대 0.08m/s, 좌우 회전 최대 0.6rad/s, 데드존 0.12이다.
- 조이스틱 입력이 0.5초 이상 끊기면 mux가 정지한다.

```bash
source /opt/ros/humble/setup.bash
source /home/user/turtlebot3_ws/install/setup.bash
ros2 launch /home/user/sw/robot/ros2_bridge/joystick_with_mux.launch.py
```

## 16. 손 방향 독립 인식

- 화면에서 손을 회전하거나 기울여도 손가락 개수, OK 사인, 손등을 동일하게 판정하도록 변경했다.
- 화면 투영과 MediaPipe 3D 월드 랜드마크를 손가락별로 융합한다.
- 정면 구도에서 3D 깊이 추정이 틀리면 화면 좌표의 펴짐이 우선하고, 손가락이 카메라 쪽을 향해 화면에서 짧아지면 3D 펴짐을 사용한다.
- 엄지 위/아래는 화면 y축이 아니라 손목→중지 MCP의 손바닥 축과 엄지 방향의 내적으로 구분한다.
- 손을 화면에서 90° 회전한 엄지 ON 판정 단위 테스트를 추가했다.
- 관련 손 제스처 테스트 31개 통과 후 서버를 재시작했다.

## 17. 제스처 반응 지연 최적화

- 일반 이동 포즈 확인을 2프레임에서 1프레임으로 줄여 첫 유효 카메라 프레임에 확정한다.
- 4손가락도 1프레임에 확정한다.
- 오작동 영향이 큰 손등 Nav2 목표는 3프레임, OK 제어권 전환은 2프레임 확인을 유지한다.
- 제스처 HTTP 브리지 폴링을 20Hz에서 카메라와 같은 30Hz로 올렸다.
- 브리지 요청 제한시간을 0.20초에서 0.15초로 줄였다.
- 속도 mux 출력 주기를 20Hz에서 50Hz로 올렸다.
- 입력 단절 정지 판단을 0.5초에서 0.3초로 줄였다.
- 30Hz `/cmd` 접근 로그를 비활성화해 CPU·디스크 로그 부하를 줄였다.
- 관련 테스트 41개 통과 후 제스처 서버·브리지·mux를 재시작했다.

## 18. 따봉·한 손가락 중복 판정 수정

- 화면·3D 손가락 융합 과정에서 따봉의 검지가 3D상 펴짐으로 튀어 `finger`가 되는 현상을 확인했다.
- 화면에서 검지~새끼 중 3개 이상이 접혔으면 엄지 ON/OFF 판정을 손가락 개수보다 먼저 수행한다.
- 따봉으로 확인되면 같은 프레임에서 `finger` 이동 명령은 발생하지 않는다.
- 잘못된 3D 검지 펴짐이 있어도 `mode_on`이 우선되는 회귀 테스트를 추가했다.
- 관련 테스트 32개 통과 후 제스처 서버를 재시작했다.

## 19. 전체 포즈 전환 중복 방지

- 1프레임 즉시 확정에서는 손가락을 펴고 접는 도중의 중간 개수도 명령으로 실행될 수 있음을 확인했다.
- 모든 이동 포즈를 2프레임 연속 확인하도록 변경해 1프레임짜리 `finger/two/three/four` 중간 신호를 차단한다.
- 카메라 30FPS 기준 확인 지연은 약 67ms이며 브리지 30Hz·mux 50Hz 최적화는 그대로 유지한다.
- 주먹 비상정지는 확인 지연 없이 즉시 처리한다.
- 엄지 ON/OFF 우선, OK 사인 우선, 손등 우선, 손가락 개수 순으로 한 프레임에서 하나의 의미만 반환한다.

## 20. 제스처 ON/OFF 및 전체 포즈 안정화

- 실시간 확인에서 따봉은 `mode_on`으로 연속 인식됐고 ROS 상태도 `/gesture_mode: true`, `/joystick_mode: false`로 확인했다.
- 실제 엄지 아래 자세가 손바닥 축에 완전히 평행하지 않아도 인식되도록 엄지 정렬 허용각을 넓혔다.
- 엄지 길이 최소 기준을 손 크기의 20%에서 15%로 완화했다.
- 화면 좌표가 명확한 손가락은 3D의 거짓 펴짐이 덮어쓰지 못하게 변경했다.
- 화면 좌표가 불명확한 손가락만 3D 월드 좌표로 보완한다.
- 따봉 우선, OK 우선, 손등 우선, 4/3/2/1개 순의 상호배타적 판정은 유지한다.
- 관련 테스트 34개 통과 후 제스처 서버를 재시작했다.

## 21. 손 자체 검출 안정화

- 실시간 장시간 수집에서 포즈 오인보다 `hand_detected=false`가 대부분인 구간을 확인했다.
- 현재 실제 사용 가능한 카메라는 `/dev/video0` 하나이므로 설정의 미연결 `/dev/video2`를 제거했다.
- 불필요한 두 번째 HandLandmarker 모델 생성도 제거되어 메모리와 초기화 부하가 줄었다.
- VIDEO 추적 중 매 프레임 입력 좌표계와 크기를 바꾸던 손 주변 ROI 크롭을 비활성화했다.
- 전체 1280×720 프레임을 동일 좌표계로 연속 추적하도록 변경했다.
- 손 검출·존재·추적 문턱을 0.30에서 0.25로 완화했다.
- 최소 손 크기 비율을 0.035에서 0.025로 완화했다.
- 카메라·추적·포즈 관련 테스트 65개 통과 후 서버를 재시작했다.
