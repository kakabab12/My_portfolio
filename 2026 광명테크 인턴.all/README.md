## 기술적으로 신경 쓴 부분

**① 얼굴 기준 좌표계 (face-local frame)**
커서 기준점을 화면이 아니라 **얼굴 자신을 기준으로** 재도록 재설계했습니다.
두 눈을 잇는 선을 얼굴의 좌표축으로 삼고 안구간 거리로 나누면,
몸이 움직여도 눈과 코가 *함께* 움직이므로 얼굴 좌표계 안의 값은 그대로입니다.
→ "가만히 있어도 커서가 밀려간다"는 문제가 **원리적으로 사라짐**.

**② 오발 방지를 규칙에 내장**
손 모양이 계층을(탐색/명령), 이동 방향이 기능을 정합니다.
탐색(한 손가락)은 아무리 반복해도 화면이 안 바뀌고, 화면을 바꾸려면 주먹을 쥐어야 합니다.

**③ 무인 운영 안정성**
카메라가 죽으면 4초 내 자동 복구, 스레드가 멈추면 감시 장치가 화면에 알림,
같은 오류가 반복되면 로그를 접어서 기록(1,200줄 → 2줄), 로그 파일 20MB 상한.

**④ 적용 기술의 출처를 밝힘**
- 1€ Filter — Casiez, Roussel, Vogel (ACM CHI 2012) — 속도 적응형 떨림 제거
- CLAHE — Zuiderveld (Graphics Gems IV, 1994) — 저조도 인식률 개선
- ISO 9241-411:2012 — 포인팅 장치 성능(처리량) 측정 표준
- 중앙값 캘리브레이션 · 히스테리시스 + 쿨다운 — 로버스트 통계 / 제어공학 기본 기법

## 대표 문제 해결

| 문제 | 어떻게 풀었나 |
|---|---|
| **깊이 센서 없이 "조작하는 사람"만 구별** | 뒷사람 손이 같이 인식돼 조작권이 넘어감. 앵커 고정 → 크기 기반 거리 추정 → 팔 길이 제약 → **배경 블러로 모델이 아예 다른 사람을 못 보게 하는 방식**까지 5단계 시도. 별도로 단안 깊이 추정(MiDaS)까지 검증해 근본 대안을 보고서로 제출 |
| **성능 가설을 두 번 오판** | "다른 프로그램이 CPU를 써서 느리다"는 가설로 최적화했으나 해결 안 됨. 항목별 실측 결과 **다른 스레드가 놀아도 항상 15~16 ms** → 추적 끝에 **윈도우 타이머 최소 단위(15.6 ms)** 가 병목임을 발견, 대기 방식 교체로 19.8→10.4 ms |
| **어림값 대신 측정 도구를 제작** | 커서가 좌우 이동 시 포물선으로 휘는 문제를 어림값으로 두 번 고치려다 악화. 곡률 실측 도구(`measure_arc.py`)를 만들어 회귀분석으로 계수를 구했고, 그 과정에서 **보정식이 화면 끝을 넘으면 발산하는 진짜 버그**를 찾아 근본 수정 + 회귀 테스트 추가 |

## 실행 환경

- **Windows + Python 3.11.5 — CPU 단독** (정부 민원발급기에는 별도 그래픽카드가 없음)
- 모델: MediaPipe FaceLandmarker / HandLandmarker (Apache-2.0, 상업적 사용 가능)
- UI 연동: **델파이 7** ← stdio 파이프로 이벤트 전달 (UDP → 웹소켓 → 파이프 순으로 변경됨)
