# 제스처 인식 모델 — 사용 설명서

키오스크 조작용 손+팔 제스처 인식 모델을 만드는 파이프라인. 웹캠 → MediaPipe로 팔/양손 관절 좌표(landmark) 추출 → 경량 PyTorch GRU로 시퀀스 분류 → `models/gesture_model.pt`.

## 왜 이렇게 만들었는지 (요약)

- **이미지가 아니라 관절 좌표로 학습.** MediaPipe 자체가 이미 아주 많은 사람 손으로 학습되어 있어서, 사람마다 다른 손 생김새/피부톤/카메라 거리 차이는 MediaPipe가 흡수해줌 → 3명만 찍어도 실전에서 꽤 일반화됨.
- **정적/동적 제스처를 하나의 구조로 통합.** 모든 제스처를 "짧은 구간(1.5초)"으로 녹화하고 고정 길이(30프레임)로 리샘플링한 뒤 시퀀스 전체를 분류함. 가만히 있는 제스처(정적)도, 스와이프처럼 움직이는 제스처(동적)도 같은 방식으로 처리됨.
- **녹화 = 자동 라벨링.** 사진 한 장씩 박스 치는 게 아니라, "이 제스처를 몇 초 녹화"하면 그 구간 전체가 자동으로 그 라벨이 됨.
- **증강으로 사람 수 부족을 보완.** 좌우반전/회전/노이즈/속도변화를 랜덤하게 걸어서, 실제 촬영한 사람 수보다 훨씬 다양한 상황에 강건해지도록 함.

## 접근성 — 피부색 · 손가락/팔 형태가 다른 사용자

키오스크는 불특정 다수가 쓰는 만큼 아래 내용을 꼭 감안해서 데이터를 모아주세요.

- **피부색**: 분류기는 이미지 픽셀을 아예 안 보고 MediaPipe가 뽑은 관절 좌표(숫자)만 보기 때문에, 피부색 자체는 분류기 입장에서 존재하지 않는 정보임. 다만 MediaPipe의 손 검출 자체가 피부색/조명에 따라 검출 품질이 달라질 수 있으니, 녹화 시 `collect_data.py` 미리보기 창에서 스켈레톤이 잘 그려지는지 눈으로 확인할 것 (안 그려지면 조명을 밝게 하거나 카메라와의 거리를 조절).
- **손가락/팔 형태가 다른 사용자**: 이건 진짜 한계가 있음 — MediaPipe의 손 검출 모델 자체가 표준적인 손가락 5개 형태 위주로 학습되어 있어서, 손 형태가 많이 다르면 애초에 좌표 추출 단계에서 잘 안 잡힐 수 있음. 이건 학습 방식(지도/비지도)을 바꿔도 못 고치는, 우리가 못 건드리는 MediaPipe 자체의 한계임. 대신 할 수 있는 것들:
  1. **다양한 사람을 실제로 녹화 데이터에 포함시키기.** 가능하면 3명 외에 손/팔 형태가 다른 분도 데이터 수집에 참여시켜서 그 사람의 실제 동작을 라벨과 함께 녹화하는 게 제일 확실한 방법 (모델은 학습 데이터에 있는 다양성만큼 일반화됨).
  2. **한쪽 손이 아예 인식 안 돼도 동작하도록 학습 시 대비함.** `augment.py`에 `HAND_DROPOUT_PROB`(기본 20% 확률)로 학습 중 한쪽 손 데이터를 통째로 지우는 증강을 넣어둠 → 모델이 팔 움직임 + 반대쪽 손만으로도 제스처를 구분하는 법을 익히게 됨. 코드 수정 없이 이미 적용되어 있음.
  3. **제스처 자체를 팔 동작 위주로 설계하는 걸 권장.** 예: `prev_menu`=팔을 왼쪽으로 스와이프, `next_menu`=오른쪽 스와이프, `home`=팔을 위로, `call_staff`=손 흔들기처럼 손가락 모양이 아니라 팔의 위치/궤적으로 구분되는 동작이면, 손가락 개수와 무관하게 인식될 가능성이 높음. 반대로 "OK 사인"이나 "숫자 세기"처럼 손가락 모양 자체가 핵심인 제스처는 손가락 형태가 다른 사용자에게 원천적으로 불리함. 어떤 제스처를 팔 동작 위주로 정의할지는 팀 UX 결정이라 제가 임의로 못 바꾸니, 원하시면 같이 정해요.
  4. **제스처만으로 100% 커버는 안 된다는 걸 전제하기.** 카메라 기반 제스처 인식은 태생적으로 모든 신체 조건을 다 커버할 수 없음. 접근성을 진지하게 고려한다면 터치스크린 버튼 같은 비-제스처 대체 입력 수단을 키오스크에 같이 두는 걸 권장 — 이건 ML 모델이 아니라 키오스크 UX 설계 영역이라 팀원들과 상의가 필요함.

## 폴더 구조

```
gesture_model/
├── config.py              # 설정: 제스처 목록, 윈도우 길이 등 (직접 실행 X, 값만 수정)
├── landmarks.py           # MediaPipe 래퍼 + 정규화/리샘플링/증강용 유틸 (라이브러리, self-test만 직접 실행)
├── augment.py             # 학습용 데이터 증강 (라이브러리)
├── dataset.py             # PyTorch Dataset (라이브러리)
├── model.py               # GRU 분류기 정의 (라이브러리)
├── collect_data.py        # [실행] 웹캠으로 데이터 녹화
├── train.py                # [실행] 학습 → models/gesture_model.pt 생성
├── infer_demo.py            # [실행] 실시간 웹캠 테스트 / 키오스크 연동 지점
├── requirements.txt
├── .gitignore
├── data/                       # 녹화된 원본 랜드마크 시퀀스 (collect_data.py가 자동 생성)
│   └── <gesture>/<person>_<gesture>_<rep>_<timestamp>.npy
└── models/
    ├── holistic_landmarker.task   # MediaPipe 사전학습 모델 (이미 다운로드됨, 13.7MB)
    ├── gesture_model.pt            # 학습된 분류기 (train.py 실행해야 생성됨)
    └── label_map.json               # 클래스 목록 등 메타데이터 (train.py 실행해야 생성됨)
```

**직접 실행하는 파일은 3개뿐**: `collect_data.py` → `train.py` → `infer_demo.py`. 나머지(`config.py` 제외)는 이 세 스크립트가 가져다 쓰는 내부 모듈.

## 0. 설치

프로젝트 폴더(`gesture_model/`)에서:

```
pip install -r requirements.txt
```

이 컴퓨터에는 이미 전부 설치돼 있음 (torch, opencv-python, numpy, mediapipe, scikit-learn). `models/holistic_landmarker.task`도 이미 받아뒀으므로 추가로 할 일 없음.

---

## 1. `config.py` — 제스처 목록 수정

직접 실행하는 파일이 아니라, 다른 모든 스크립트가 참조하는 설정 파일. **제스처를 추가/삭제하려면 이 파일의 `GESTURES` 리스트만 고치면 됨**:

```python
GESTURES = [
    "idle",         # 대기 / 제스처 아님 (필수 — 지우지 말 것)
    "select",
    "confirm",
    "home",
    "prev_menu",
    "next_menu",
    "call_staff",
    "zoom_in",      # <- 이런 식으로 새 제스처는 이름만 추가하면 됨
]
```

이름은 영문 slug로 (파일/폴더 이름으로 그대로 쓰이기 때문). 추가한 뒤에는 `collect_data.py`로 새 제스처 데이터를 녹화하고 `train.py`를 다시 돌리면 됨. `idle`은 오탐(false trigger) 방지에 필수라서 절대 빼면 안 됨.

기타 설정:
- `WINDOW_SECONDS` (기본 1.5초): 제스처 하나를 녹화/인식하는 시간 길이
- `SEQ_LEN` (기본 30): 그 구간을 몇 프레임으로 리샘플링해서 모델에 넣을지
- `ARM_LANDMARK_IDS`: 팔에서 추적할 관절 (어깨/팔꿈치/손목) — 보통 안 건드려도 됨

---

## 2. `collect_data.py` — 데이터 녹화 (3명이 각자 실행)

```
python collect_data.py
```

1. 실행하면 `촬영 대상 이름을 입력하세요` 라고 물어봄 → `kim`, `lee`, `park`처럼 사람마다 다른 이름 입력 (같은 이름을 두 번 쓰면 그 사람 데이터에 이어서 추가됨)
2. 웹캠 창이 뜨고, 화면에 팔/손 스켈레톤이 그려짐
3. 화면 하단 안내대로 키 조작:
   - **SPACE**: 3초 카운트다운 후 1.5초간 자동 녹화 (녹화 중엔 화면에 `REC` 표시)
   - **n / p**: 다음/이전 제스처로 전환 (화면 상단에 현재 제스처명과 지금까지 녹화한 개수가 표시됨)
   - **q**: 종료
4. 녹화된 파일은 `data/<제스처>/<이름>_<제스처>_<번호>_<타임스탬프>.npy` 로 자동 저장됨

**권장 녹화량**: 제스처당 **최소 15~20회 이상**, 매번 위치/각도/속도/거리를 조금씩 바꿔가며 녹화. 3명이 같은 방식으로 하면 됨.

**`idle` 클래스가 제일 중요함**: 가만히 서있기, 손 내리고 자연스럽게 서있기, 얼굴/머리 만지기, 옆 사람과 손짓하며 대화하기 등 "제스처가 아닌 모든 자연스러운 동작"을 다양하게 녹화해야 실제 키오스크에서 아무 동작에나 반응하는 오작동을 줄일 수 있음. 다른 제스처보다 오히려 더 많이(예: 30회 이상) 녹화하는 걸 추천.

**3명이 다른 컴퓨터에서 녹화한 경우**: 각자의 `data/` 폴더를 합쳐서 한 곳의 `data/` 폴더로 모은 뒤 `train.py`를 실행하면 됨 (같은 제스처 폴더끼리 파일을 합치면 되고, 파일명에 이름이 들어있어서 겹칠 걱정은 없음).

---

## 3. `train.py` — 학습

`data/` 에 녹화가 어느 정도 쌓인 뒤:

```
python train.py
```

기본값: 100 epoch, batch size 16. 옵션으로 조절 가능:

```
python train.py --epochs 150 --batch_size 32 --lr 0.001 --val_ratio 0.2
```

| 옵션 | 기본값 | 의미 |
|---|---|---|
| `--epochs` | 100 | 전체 데이터를 몇 번 반복 학습할지 |
| `--batch_size` | 16 | 한 번에 학습에 넣는 샘플 수 (데이터가 적으면 8로 낮춰도 됨) |
| `--lr` | 1e-3 | 학습률 |
| `--val_ratio` | 0.2 | 전체 데이터 중 검증용으로 떼어둘 비율 |

**출력 읽는 법**:
- 시작할 때 클래스별 샘플 수가 출력됨 → 특정 제스처가 너무 적으면 더 녹화 권장
- `val_acc`: 검증 정확도. 1.0에 가까울수록 좋음 (다만 데이터가 아주 적으면 과대평가될 수 있으니, 결국 `infer_demo.py`로 실제 테스트해보는 게 제일 정확함)
- 학습이 끝나면 confusion matrix와 클래스별 precision/recall이 출력됨 → 어떤 제스처끼리 헷갈리는지 확인 가능. 특정 제스처의 recall이 낮으면 그 제스처를 더 녹화하고 재학습.

결과물: `models/gesture_model.pt` (학습된 가중치), `models/label_map.json` (클래스 목록·입력 차원 등 메타데이터, `infer_demo.py`가 읽어서 모델 구조를 복원하는 데 씀). **재학습하면 두 파일 다 덮어써짐.**

## 4. `infer_demo.py` — 실시간 테스트 / 키오스크 연동

`models/gesture_model.pt`가 있어야 실행 가능:

```
python infer_demo.py
```

웹캠 창에 현재 예측 중인 제스처와 confidence가 실시간으로 표시됨. 어떤 제스처가 confidence 기준을 넘고, 최근 몇 프레임 연속으로 같은 제스처가 나오면 "확정"되어 콘솔에 `>>> GESTURE: xxx (0.9x)` 로 출력됨 (한 번 확정되면 잠깐 재발화를 막는 쿨다운이 있어서 같은 제스처가 연타로 찍히지 않음). `q`로 종료.

**팀원 키오스크 프레임워크와 연동하는 지점**은 파일 상단의 이 함수 하나뿐:

```python
def on_gesture_detected(label: str, confidence: float):
    print(f">>> GESTURE: {label} ({confidence:.2f})")
```

이 함수 내용을 실제 키오스크 동작(화면 전환 함수 호출, 이벤트 큐에 넣기, 소켓으로 전송 등)으로 바꿔 끼우면 됨. `label`은 `config.py`의 `GESTURES`에 적은 이름 그대로 문자열로 들어옴 (예: `"select"`, `"next_menu"`).

**오탐이 너무 잦거나 반응이 너무 둔하면** 파일 상단 상수를 조절:

| 상수 | 기본값 | 올리면 | 내리면 |
|---|---|---|---|
| `CONFIDENCE_THRESHOLD` | 0.80 | 더 확실할 때만 반응 (오탐↓, 반응성↓) | 더 잘 반응 (오탐↑) |
| `CONSECUTIVE_HITS_REQUIRED` | 4 | 더 안정적 (오탐↓, 느려짐) | 더 빠르게 확정 (오탐↑) |
| `COOLDOWN_FRAMES` | 20 | 연타 방지 강화 | 같은 제스처 빨리 재인식 |

## 5. 내부 모듈 (보통 직접 안 건드려도 됨)

- **`landmarks.py`**: MediaPipe HolisticLandmarker를 감싸서 프레임 하나를 152차원 벡터로 뽑아주는 `HolisticExtractor`, 그리고 정규화(`normalize_frame`)/리샘플링(`resample_sequence`)/좌우반전(`mirror_frame`)/회전(`rotate_frame`) 함수들이 들어있음. `collect_data.py`, `train.py`(내부적으로 `dataset.py` 경유), `infer_demo.py`가 전부 이 파일을 공유해서 씀 — **학습 때 쓰는 정규화와 추론 때 쓰는 정규화가 어긋나면 모델이 무조건 틀어지기 때문에 단일 소스로 유지하는 게 중요함**. 좌표 인덱스 계산이 손으로 짠 부분이라, `python landmarks.py`로 실행하면 자체 검증(self-test)이 돌아감 — 이 파일을 수정했다면 한 번 실행해서 통과하는지 확인 권장.
- **`augment.py`**: `train.py` 학습 중에만 쓰이는 증강 함수. 증강 강도를 바꾸고 싶으면 `MAX_ROTATION_RAD` 값 조절. `HAND_DROPOUT_PROB`는 학습 중 한쪽 손을 통째로 지워서 손 인식이 안 되는 상황에도 강건하게 만드는 비율 (접근성 관련, 위 섹션 참고).
- **`dataset.py`**: `data/` 폴더를 읽어서 PyTorch가 쓸 수 있는 형태로 바꿔주는 코드.
- **`model.py`**: GRU 분류기 구조 정의. 데이터가 아주 많아져서 모델을 키우고 싶으면 `GestureGRU(hidden_dim=...)` 값을 키우면 됨 (지금은 소량 데이터에 맞춰 작게 잡아둠).

## 전체 워크플로우 요약

1. `python collect_data.py` — 3명이 각자 실행, 제스처당 15~20회+ (idle은 30회+) 녹화
2. 3명의 `data/` 폴더 내용을 하나로 합치기
3. `python train.py` — `models/gesture_model.pt` 생성
4. `python infer_demo.py` — 실시간으로 확인, 잘 안 되는 제스처 있으면 그 제스처만 더 녹화 후 2~3번 반복
5. `infer_demo.py`의 `on_gesture_detected()`를 팀원 키오스크 코드와 연결

## 트러블슈팅

- **`웹캠을 열 수 없습니다` 에러**: 다른 프로그램(Zoom, 다른 파이썬 스크립트 등)이 웹캠을 이미 점유하고 있는지 확인. `cv2.VideoCapture(0)`의 `0`을 `1`로 바꿔서 다른 카메라 인덱스도 시도해볼 것.
- **`모델 파일이 없습니다: ...holistic_landmarker.task` 에러**: `models/` 폴더에 그 파일이 있는지 확인 (13.7MB). 없으면 `https://storage.googleapis.com/mediapipe-models/holistic_landmarker/holistic_landmarker/float16/latest/holistic_landmarker.task` 에서 받아서 `models/holistic_landmarker.task`로 저장.
- **`학습 데이터가 없습니다` 에러**: `data/` 밑에 제스처별 폴더/`.npy` 파일이 있는지 확인. `collect_data.py`를 먼저 실행해야 함.
- **특정 제스처만 자꾸 다른 걸로 오인식**: `train.py` 출력의 confusion matrix에서 그 제스처 행을 확인 → 헷갈리는 제스처와 동작 자체가 너무 비슷하지 않은지 점검, 그리고 그 제스처를 더 다양하게(위치/각도/속도) 추가 녹화 후 재학습.
- **가만히 있어도 제스처가 자꾸 인식됨(오탐)**: `idle` 데이터를 더 다양하게 녹화하거나, `infer_demo.py`의 `CONFIDENCE_THRESHOLD`/`CONSECUTIVE_HITS_REQUIRED`를 올려서 재시도.
